## Goal

A file tool's ask on watane's host offers Alice "Allow `Read(<workspace folder>/**)` this session"
again, now from the path the host resolved, never from the input `claude` sent. Since watane S100
the host gives a file-tool `ask`/`check` item a top-level `path`: absolute, symlinks resolved,
absent when it cannot resolve it or its rule refuses it (Deputy decisions, 2026-11-23; host 19.3
step 4). The kernel keeps that `path` on the ask entry and computes the file key only from it.

The decision this task makes at the security boundary (14, "A session allow reaches no more than
its key"): where the kernel learns the workspace's own folder, which the `<ws>/**` key needs and the
record does not hold (the record's `workspace` is the host's id `scratch:<32 hex>`). It is the
`cwd` of the stream's first `system/init` line: `claude` reports its process folder, which the host
set to the workspace folder (host 19.3 "Folders"), as `getcwd` gives it (symlinks resolved, as the
host resolves `path`). The record keeps it once as `folder`, like `workspace`; a later `system/init`
with another `cwd` changes nothing. No `folder`, or no `path`: no file key (the ask still asks).

## Acceptance

AC1. Adapter (9.8): an `ask` or `check` item with a top-level `"path":"/w/a.txt"` gives an ask entry
     whose body holds `"path":"/w/a.txt"` (after `input`); with no `path`, or a `path` that is not a
     string, the body has no `path` and the item is still an ask (no `unknown`).
AC2. `system/init` with `"cwd":"/w"` (and a `session_id`) sets the record's `folder` to `/w` once; a
     second `system/init` (same or later stream) with `"cwd":"/x"` leaves it `/w`. A `cwd` that is not
     a plain absolute folder (not starting `/`, ending in `/`, holding `(`, `)` or a control
     character) sets nothing. No entry is written for either.
AC3. Key from `path` (9.6): with `folder` `/w`, an ask `Read` with input `{"file_path":"rel/../../etc/x"}`
     and `path` `/w/a/b.txt` gets reach `Read(/w/**)`; the same ask with `path` `/etc/passwd`, or with
     no `path`, gets no reach; an ask whose input path is `/w/a.txt` but whose `path` is `/elsewhere/a.txt`
     (a symlink the host resolved) gets no reach. With no `folder`, no file ask gets a reach.
AC4. The segment rules of 9.6 apply to `path` after `folder/`: `Write` to `/w/.git/config`,
     `/w/sub/Makefile`, `/w/CLAUDE.md`, a path with a byte outside printable ASCII, and any path with an
     empty segment get no reach; `Read` of `/w/.git/config` gets `Read(/w/**)` (reads may name dot
     files, as today). `Glob` and `Grep` with `path` equal to `/w` (their path input absent: the working
     folder) get `Glob(/w/**)`/`Grep(/w/**)`; `Read`, `Edit`, `Write`, `NotebookEdit` with `path` equal to
     `/w` get none. The `Glob` `pattern` rule and the known-keys rule stay as they are.
AC5. Session allow end to end in the crate: allow `{"allow":true,"for":"session"}` on AC3's first ask
     stores `(Read, /w/**)`; a later `Read` ask with `path` `/w/c.txt` is answered by the kernel
     (`allow, by: session-allow`, `Request::Answer` allow); a later one with `path` `/etc/passwd` opens
     for the owner. A `take-back` makes the next `/w/...` ask open for the owner again.
AC6. Existing broker and scope tests that fed an absolute `workspace` and an input path now feed
     `folder` and `path`; none is deleted; the cases they assert (dot segments, named files, ASCII,
     Glob pattern, known keys, Bash, WebFetch, Skill, TodoWrite) still hold.
