## Goal

A code block an agent writes can no longer freeze the page: Shiki runs in a Web Worker, and each
block has a time budget of 250 ms (wall clock from when the Worker gets it). Past the budget the
Worker is ended, the block stays plain, and the blocks behind it go to a fresh Worker (S7 RISK b,
18.6 Long sessions). A test feeds a known backtracking input and shows the page stays responsive.

## Acceptance

AC1. Off the main thread. In the browser, `highlight(lang, code)` tokenizes in a module Worker
     loaded from a same-origin chunk (`new Worker(new URL("./highlight.worker.ts", import.meta.url), { type: "module" })`
     or equivalent that vite emits as a file in `ui/`); the main thread never runs Shiki's
     tokenizer. Results, cache (200 entries / 2 MiB) and the 64 KiB `MAX_CODE` limit stay as today.
AC2. Budget. `HIGHLIGHT_BUDGET_MS = 250` exported from `kit/parts/highlight.ts`. A block whose
     tokens do not come back within it resolves `null` (stays plain, cached as plain so it is not
     retried), the Worker is terminated, and the next queued block starts on a new Worker within
     one budget. Blocks are sent one at a time, in order of request.
AC3. Fallback. Where `Worker` is undefined (jsdom, node tests), the block stays plain unless a test
     injects a tokenizer: export a seam (e.g. `setWorkerFactory` / `__setTokenizerForTests`) so unit
     tests drive the queue, the budget and the termination with a fake Worker and fake timers.
AC4. Unit test (`kit/`): a fake Worker that never answers for block A and answers at once for B:
     A stays plain after 250 ms, A's Worker got `terminate()`, B is highlighted; a third request
     for A does not start a Worker.
AC5. Real backtracking (slow, `test/`, Chromium on the built page or a dedicated harness page in
     the build): a block in a language whose grammar backtracks on a known input (find one, e.g. a
     long line that drives a Shiki grammar's regex into catastrophic backtracking; or, if none is
     found within reason, a test-only grammar registered with a pattern like `^(a+)+$` on
     `"a".repeat(40) + "!"`) stays plain, the main thread has no task over 100 ms while it runs
     (a `requestAnimationFrame` loop or `PerformanceObserver` long tasks), and a normal block after
     it is highlighted.
AC6. The build check (`test/build.test.ts`) still passes for every file in `ui/` including the
     Worker chunk: same-origin, no inline script, no `eval`/`Function(` call, no WebAssembly. If
     the check needs to learn a Worker file, it learns it without weakening any rule.
AC7. `code_S7_3.test.tsx` passes with assertions unchanged except where a test depended on Shiki
     running in jsdom on the main thread; such a test moves to the injected tokenizer and says so.
AC8. `npm test` stays within 14.5 s on this machine, or grows less than 5% from its time at the
     start of the task (report both).
