## Goal

A new native Rust crate `agent-kernel` in `kernel/` (library only; no WIT, no host, no wasm
target yet) that holds the kernel's error type and its profile check: it parses a profile
document, finds every field outside its grammar, and applies the refuse table of TECHNICAL 11
for a chosen backend and model, returning every refusal at once and never dropping a field.
Overlays and the `check` example are task S3-2.

## Acceptance

AC1. `kernel/Cargo.toml` declares package `agent-kernel` (edition 2021, `publish = false`,
     license `MIT OR Apache-2.0`); `cargo test` and `cargo clippy --all-targets -- -D warnings`
     pass in `kernel/` with no host and no network beyond crates.io. `Cargo.lock` is committed.
AC2. Errors (TECHNICAL 12 kernel rows, AGT-F-40): `KernelError::code()` returns exactly
     `not-owner`, `unknown-session`, `refused`, `queue-full`, `quota`, `paused`, `backend`,
     `unknown-input`, `unknown-allow`, `behind` for its ten variants; `Display` of each names
     the cause (the session id, the input number, the time, the refused fields, ...). A test
     lists all ten codes and checks each message contains its variant's data.
AC3. `parse_profile` on JSON that is not an object, or not JSON, returns one problem with field
     `profile` and a reason naming the parse error.
AC4. Unknown keys: each is a problem naming that key (`"reason": "not a profile field"`). The
     per-session keys `workspace`, `extra-workspaces`, `agent-handle`, `session` are each a
     problem with reason "chosen per session, not in a profile (9.2)".
AC5. Grammar (TECHNICAL 4.1, 4.2, 9.2): each of these is a problem naming its field, and all are
     reported together from one document: `model`/`fallback-models` entries outside
     `[A-Za-z0-9.\-\[\]]{1,64}`; more than 4 fallback models; `effort` outside the 5 levels;
     `mode` outside `manual|accept-edits|plan|dont-ask` (so `auto` and `bypassPermissions` are
     refused); `system-prompt` not exactly one of `replace`/`append` or over 64 KiB; a `tools`
     name outside the allowlist of 4.2 (`claude-code-shell`'s list); an `allow`/`deny` rule
     outside the rule grammar of 4.1 (name from the allowlist or `mcp__watane__<tool>`, no
     comma, space or leading `-` outside the parentheses); an `allow` `Bash(<prefix>…)` whose
     prefix starts with an interpreter or runner (at least `bash`, `sh`, `zsh`, `fish`, `dash`,
     `env`, `python*`, `node`, `deno`, `bun`, `bunx`, `npx`, `npm exec`, `pnpm dlx`, `uvx`,
     `uv run`, `devbox run`, `perl`, `ruby`, `php`, `eval`, `exec`, `xargs`, `sudo`);
     `pre-tool-check.timeout-s` outside 5..120; a subagent with any key besides `name`,
     `description`, `prompt`, `tools`, `model` (each extra key named, e.g.
     `subagents[0].permissionMode`), a name outside `[a-z0-9-]{1,64}`, `tools` not a subset of
     the profile's `tools`, or subagents over 64 KiB in all; `subagent-depth` outside 0..3;
     a skill name outside `[a-z0-9-]{1,64}`, a file path that is absolute or has a `..`
     segment, or skills over 1 MiB in all; `json-schema` over 64 KiB; `max-turns` outside
     1..1000; `max-budget-usd` not positive; `max-tool-errors`, `max-tokens` not positive;
     `backend` not `claude`/`openai`; a value of the wrong JSON type.
AC6. A profile that passes AC3–AC5 and the table yields no refusals for `claude` and a model
     such as `claude-opus-5-5`, and the parsed `Profile` keeps every field it was given (a
     round-trip test: parse, serialize, compare as `serde_json::Value`).
AC7. Refuse table, OpenAI (TECHNICAL 11, AGT-F-4): one profile with non-empty `tools`
     (`Read`, `Edit`), `sandbox`, `max-budget-usd`, an `allow` path rule `Read(./src/**)`,
     non-empty `fallback-models`, `mode: plan`, a subagent with `tools`, and a skill with a file
     besides `SKILL.md` yields, for `openai`, one refusal for each of those fields (nested ones
     named like `subagents[0].tools`, `skills[0].files`), every one at once, each with
     `backend: "openai"` and the given model. A path rule is an `allow`/`deny` rule `Name(arg)`
     whose Name is `Read`, `Write`, `Edit`, `Glob`, `Grep` or `NotebookEdit`.
AC8. Refuse table, Claude: `ask-expiry` other than 600 (seconds) is refused; `tools` with
     `Bash`, `WebFetch` or `WebSearch` and no `sandbox` is refused naming `sandbox` (4.2); the
     same profile with a `sandbox` object passes.
AC9. Models (TECHNICAL 11 `model`, `effort`): with a `Catalog`, an `openai` model not in it is
     refused naming `model`, and an `effort` the model does not list is refused naming
     `effort`. Without a catalog neither is checked. The model argument is checked against the
     4.1 model grammar on both backends either way.

## Spec

TECHNICAL 4.1 (grammar), 4.2 (grants, tool allowlist), 9.2 (profile fields), 11 (refuse
table), 12 (kernel error rows), 13 (libraries); FUNCTIONAL AGT-F-4, AGT-F-40. Do not edit
`design/`: slice S2 rewrites it now. A spec question goes under `QUESTIONS` and you build the
option the brief states.

Decisions the foreman made where the spec is open (follow them):
- The model and backend under check are arguments; a profile's own `backend` and `model` are
  defaults and are only grammar-checked.
- `ask-expiry` is a whole number of seconds. `skills` is a list of `{name, files}` where
  `files` maps a relative path to its text. `sandbox` and `subagent-limits` are kept as raw
  JSON objects (their typed record, 4.2, is a later slice); `json-schema` is raw JSON.
- Refusals that come from the document itself (AC3–AC5) carry the backend and model under
  check like any other.

## Interface

Provided to S3-2 (fixed; all public from the crate root):
```rust
// kernel/src/error.rs
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct Refusal { pub field: String, pub backend: String, pub model: String, pub reason: String }
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Problem { pub field: String, pub reason: String }
impl Problem { pub fn refusal(&self, backend: Backend, model: &str) -> Refusal; }
#[derive(Debug, Clone, PartialEq)]
pub enum KernelError { NotOwner, UnknownSession(String), Refused(Vec<Refusal>), QueueFull,
  Quota, Paused(u64), Backend(String), UnknownInput(u64), UnknownAllow(String), Behind(u64) }
impl KernelError { pub fn code(&self) -> &'static str; }   // plus Display, std::error::Error
// kernel/src/profile.rs
#[derive(Debug, Clone, Copy, PartialEq, Eq)] pub enum Backend { Claude, Openai }
impl Backend { pub fn as_str(self) -> &'static str; }       // "claude", "openai"
impl std::str::FromStr for Backend { type Err = String; }
#[derive(Debug, Clone, Default, PartialEq, Serialize, Deserialize)]
#[serde(rename_all = "kebab-case")]
pub struct Profile { /* every field of 9.2, Option or Vec, skipped when empty on serialize */
  pub system_prompt: Option<SystemPrompt>, pub tools: Vec<String>, pub allow: Vec<String>,
  pub deny: Vec<String>, pub mode: Option<String>, pub skills: Vec<Skill>,
  pub subagents: Vec<Subagent>, pub subagent_depth: Option<u8>, pub max_turns: Option<u32>,
  pub max_tool_errors: Option<u32>, pub max_tokens: Option<u64>, pub max_budget_usd: Option<f64>,
  /* ...and the rest */ }
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[serde(rename_all = "kebab-case")]
pub enum SystemPrompt { Replace(String), Append(String) }
pub struct Skill { pub name: String, pub files: std::collections::BTreeMap<String, String> }
pub struct Subagent { pub name: String, pub description: String, pub prompt: String,
  pub tools: Vec<String>, pub model: Option<String> }
pub fn parse_profile(json: &str) -> (Profile, Vec<Problem>);  // keeps every valid field
pub fn grammar_problems(p: &Profile) -> Vec<Problem>;         // AC5 rules on a typed profile
// kernel/src/refuse.rs
#[derive(Debug, Clone, Default, Deserialize)] pub struct Catalog { pub models: Vec<CatalogModel> }
#[derive(Debug, Clone, Deserialize)] pub struct CatalogModel { pub slug: String, pub efforts: Vec<String> }
pub fn refuse(p: &Profile, backend: Backend, model: &str, catalog: Option<&Catalog>) -> Vec<Refusal>;
```
`grammar_problems` exists so S3-2 can re-run the grammar on a profile after an overlay changed
it. `parse_profile` runs it itself. Field names in problems are the document's own keys,
nested as `subagents[0].tools`.
