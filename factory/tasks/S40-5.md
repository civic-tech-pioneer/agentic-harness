## Goal
The kernel mod, as watane runs it, can do what S40-3 and S40-4 built: its world imports
`https-stream` and `agent-tools`, its manifest grants it `api.openai.com`, and its `sessions`
interface lets every client (the console too) list the profiles it may use and check one by name,
so a client sees each field a backend cannot honour before anything starts (AGT-F-5, AGT-F-46).

## Acceptance
AC1 `kernel/wasm/wit/world.wit` imports `watane:host/https-stream@0.1.0` and `watane:host/agent-tools@0.1.0`; `WitHost` implements `https_start` (an `Err` is the `start-error` as `map::start_error` names it) and `tools_open`/`tools_describe`/`tools_call`/`tools_close` (an `Err` is the `tools-error` case in kebab-case, `consent-pending(<what>)` and `consent-refused(<what>)` with their text); unit tests in `map.rs` map every case.
AC2 `kernel/wasm/mod.toml` has `[http]` `hosts = ["api.openai.com"]`; the component builds (`cargo build --release --target wasm32-wasip2 -p agent-mod` in `kernel/`).
AC3 `sessions.check(profile, overlay)` is the crate's `Kernel::check_named(caller, profile, overlay)`: a name the caller may not use is one refusal `{field: "profile"}` (9.1, whether or not it exists); a usable name with no stored profile (other than the built-in `scratch`) is one refusal `{field: "profile", reason: "no such profile"}`; otherwise every refusal of `check` (9.2) for the profile's backend and model (an OpenAI profile without a model: `{field: "model"}`). An OpenAI profile with `tools: ["Read"]` gives the `tools` refusal; one with `skills` gives a `skills` refusal ("skills wait for the skill tool on openai", until stage F's `skill` tool) — add that row to the refuse table (`kernel/src/refuse.rs`) and to TECHNICAL 11.
AC4 New `sessions.profiles: func() -> list<profile-info>`, `record profile-info { name: string, backend: string, model: option<string> }`: the profiles the caller may use (9.1 `access/<identity>`; for `page` with no `access/page`, the built-in `scratch`), in the access list's order, at most 64 (the rest are left out), each read from `profile/<name>` (`backend` defaults to `claude`); a listed name with no stored profile is left out. The crate's `Kernel::profiles(caller) -> Vec<ProfileInfo>`; reads at most 65 state keys.
AC5 TECHNICAL 2.3's WIT block and the 9.1 `access/` row say what AC3 and AC4 do; section 14's row "The console has no power a client lacks" still holds (both calls are on the interface every client has).
