## Goal

The kernel has the OpenAI rule matcher of 9.6 as a pure function with tests:
a profile's `allow`, `ask` and `deny` rule lists compile into a `Rules`
value, path rules are refused at compilation, and `Rules::decide(tool, arg)`
says `Allow`, `Ask` or `Deny` for one tool call. Nothing calls it yet: the
OpenAI loop (9.5, stage D) will broker each call with it, and its kernel
asks' `ask-expiry` deadline waits for that loop.

Spec (TECHNICAL 9.6, quoted):
> - Rules: deny, then ask, then allow; the strictest match wins. A rule that
>   does not parse disables its tool. A tool that no rule names asks.
> - Matching for OpenAI: tool names and `Name(arg)` with `*` and `?` globs;
>   path rules are refused at compilation.

Decisions the foreman made (build them as written):
- A rule is `Name` or `Name(arg)`. `Name` is 1 to 64 of `A-Za-z0-9_-`
  (OpenAI's function-name grammar). `arg` is non-empty, has no `(` or `)`,
  and no rule has a control character. Anything else does not parse.
- "Does not parse": when the text before the first `(` (or the whole rule,
  with no `(`) is a valid `Name`, that tool is disabled: every call of it is
  `Deny`. When no valid `Name` can be read, the rule is refused at
  compilation as a problem (there is no tool to disable).
- A path rule is one whose `arg` starts with `/`, `~`, `./` or `../`, is `.`
  or `..`, or contains `**`. It is refused at compilation as a problem.
- Globs: `*` matches any run of characters (empty included, `/` included),
  `?` exactly one character (a Unicode scalar), every other character
  itself; the whole `arg` must match. Matching is linear-ish (no exponential
  backtracking).
- A bare `Name` matches every call of that tool; `Name(pat)` matches a call
  whose `arg` is `Some` and matches `pat`; a call with `arg: None` matches
  only bare rules. Names are case-sensitive.
- `decide`: disabled tool or any matching deny -> `Deny`; else any matching
  ask -> `Ask`; else any matching allow -> `Allow`; else `Ask` (a tool no
  rule names, or none of whose rules match, asks).

## Acceptance

AC1. `compile(&["read"], &[], &[])` then `decide("read", None)` and
`decide("read", Some("x"))` are `Allow`; `decide("write", None)` is `Ask`.

AC2. Strictest wins: allow `shell`, ask `shell(git push*)`, deny
`shell(rm *)`: `shell` with `git status` -> `Allow`, `git push origin` ->
`Ask`, `rm -rf x` -> `Deny`. The same with the deny also listed in allow
(`allow: ["shell(rm *)"]`) is still `Deny`.

AC3. Globs: allow `fetch(https://example.com/*)`: `https://example.com/a/b`
-> `Allow`, `https://example.org/` -> `Ask`. Allow `get(v?)`: `v1` -> `Allow`,
`v12` and `v` -> `Ask`; `?` matches one non-ASCII character (`vé` ->
`Allow`). A literal match needs the whole arg: allow `f(ab)` and arg `abc` ->
`Ask`. A call with `arg: None` against only `f(*)` -> `Ask`.

AC4. A rule that does not parse disables its tool: each of `shell(`,
`shell(a(b))`, `shell()`, `shell(a)x`, and a rule with a control character
after a valid name (`shell(a\nb)`), listed in any of the three lists, makes
every `shell` call `Deny`, even when another rule allows it; other tools are
unaffected and compile gives no problem for these.

AC5. Path rules are refused at compilation: `read(/etc/*)`, `read(~/x)`,
`read(./x)`, `read(../x)`, `read(.)`, `read(src/**)` each give one problem
whose `field` is the list's name (`allow`, `ask` or `deny`) and whose reason
names a path rule. A rule with no readable name (`(x)`, `a b`, empty
string, a name of 65 characters) gives one problem too.

AC6. Case: allow `Read` does not allow `read`.

AC7. A pathological pattern (`*a*a*a*a*a*a*a*a*b` against 20 000 `a`)
decides within 1 second in a debug build (assert with a timer in the test).

AC8. `cargo test`, `cargo clippy --all-targets -- -D warnings`,
`cargo fmt --check` and `factory/gate.sh` pass.

## Interface

Provides (fixed), in `kernel/src/rules.rs`, `pub mod rules;` in
`kernel/src/lib.rs`, re-exported as `pub use rules::{Rules, Verdict};`:
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Verdict { Allow, Ask, Deny }
pub struct Rules { /* private */ }
impl Rules {
    /// Problems are path rules and rules with no readable name; the Rules are usable anyway.
    pub fn compile(allow: &[String], ask: &[String], deny: &[String]) -> (Rules, Vec<Problem>);
    pub fn decide(&self, tool: &str, arg: Option<&str>) -> Verdict;
}
```
Takes nothing from a sibling. S31-2 also adds a `pub mod` line to `lib.rs`;
add only your own line.
