## Goal

One gate script for the whole project, `factory/gate.sh`, that runs every part that exists, so
the factory's check and CI test the kernel crate (and later the console) and not only the
Markdown links. `factory/config.toml` names it as the gate.

## Acceptance

AC1. `factory/gate.sh` (POSIX `sh` or `bash`, executable, a header comment saying what it runs
     and citing this slice's plan entry) runs from the project root, in this order, stopping at
     the first failure with a non-zero exit:
     1. `.claude/factory/check-mod.sh` always (it checks the Markdown links, and runs
        `watane-dev` only when `wit/world.wit` exists);
     2. when `kernel/Cargo.toml` exists: in `kernel/`, `cargo test` then
        `cargo clippy --all-targets -- -D warnings`;
     3. when `console/package.json` exists: in `console/`, `npm ci` then `npm test`.
     Each step echoes one line naming itself before it runs; a part that is absent echoes one
     line saying it was skipped.
AC2. `factory/config.toml`'s `gate` line is `gate = "factory/gate.sh"`, and only that line
     changes (the comment above it may say what the script runs).
AC3. Shown by running it: with no `kernel/` and no `console/` the script exits 0 and prints
     the two skip lines; in a scratch copy with a `kernel/Cargo.toml` whose test fails it exits
     non-zero; with a `console/package.json` whose `test` script is `exit 1` it exits non-zero.
     Put these three runs in `factory/gate-test.sh` (run by hand; it builds its fixtures in a
     temporary folder and never touches the real `kernel/` or `console/`), and run it once.
AC4. `.claude/factory/check.sh S3-3` passes in this worktree.
