## Goal

Alice can manage what she queued (AGT-F-50, TECHNICAL 18.6 "Queue", FRONTEND-2 row 7). Today the dock
lists the queued inputs and nothing more. After this task each queued input (of the 3 shown) has Edit,
which takes it back into the composer (`unqueue`, then its text in the composer, unless she has typed
since: then nothing is unqueued and a one-line note says the composer is in use), and Remove, which
`unqueue`s it and shows "Removed. Undo" for 6 s; Undo `say`s the same input again (it joins the end
of the queue, or starts a turn if the turn ended meanwhile). "Stop and send" on a queued input interrupts
the turn with it as the replacement (`unqueue` it, then `interrupt(session, input)`). A full queue (32
inputs, or `queue-full` from the kernel) turns Send off and the placeholder says why (as today, check
it still holds). An `unknown-input` refusal (the turn took it first) says so in one line and changes
nothing.

## Acceptance

AC1. With 2 queued inputs on a fake kernel, Edit on the first calls `unqueue(session, n)` with its `n`
     and the composer then holds its text; the queue push that follows shows one input.
AC2. Edit while the composer holds typed text: no `unqueue` call; a line says "Finish or clear your message
     first" (one `role="status"` line); the queue is unchanged.
AC3. Remove calls `unqueue`; "Removed. Undo" shows; Undo within 6 s calls `say` with the same input
     JSON; after 6 s (fake timers) the Undo is gone and no `say` is made.
AC4. "Stop and send" calls `unqueue(n)` and then `interrupt(session, <that input>)`, in that order; the
     status line shows Stopping… until the turn update.
AC5. `unqueue` refused `unknown-input`: the line "That message was already sent" shows; no other call.
AC6. Each control has an accessible name naming the input ("Edit queued message 1", "Remove queued
     message 1", "Stop and send queued message 1"); every control is reachable by keyboard.
