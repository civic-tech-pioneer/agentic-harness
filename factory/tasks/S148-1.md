Slice: S148 — OpenAI sessions use the skills named in their profiles

## Goal

An OpenAI session lists and reads its effective skills through a brokered function. Delegates can carry only the exact skill snapshots already available to the root.

## Acceptance

1. AC1: Two profile skills appear in the first request with escaped descriptions. A permitted call returns the exact selected SKILL.md and completes an ordinary transcript tool row.
2. AC2: Unknown names and malformed calls fail visibly. Extra files and missing SKILL.md produce a field refusal at check and launch.
3. AC3: An admitted child lists only its own subset. A delegate with a new name or changed file is refused before creating a child.
4. AC4: Fresh and cached toolset descriptions collide on an active skill name before a request. A profile without skills has no built-in skill.
5. AC5: Claude continues passing skill files in its plugin launch.

## Interface

The Responses function is skill(name: string). A successful output is the exact SKILL.md string. The existing internal Skill value holds the profile name and files; compilation pins these values and admission compares them by equality. Kernel exports and WIT retain their existing types.
