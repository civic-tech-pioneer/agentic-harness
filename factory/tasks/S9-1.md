## Acceptance

AC1. A `tool` row with an open ask on an edit call renders a header with an `svg` pencil icon
     (aria-hidden), the word "Edit", the path in a `code` element, and a tag with the text
     "Waiting for you"; no element of the card shows "Pending". A tool row's tag per status
     otherwise: in_progress "Running", completed "Done", failed "Failed", pending (no ask)
     "Pending"; each tag has its own class (frame `.b-wait`, `.b-ok`, `.b-bad`, `.b-off`).
AC2. An ask whose call has `diff` content shows that diff as the body and does not show the ask
     input as a key/value list (no `file_path` text in the card). An ask whose call has no diff
     content (a Bash command) still shows its input as today, so the participant always sees the
     call that will run (TECHNICAL 14, "An ask shows the tool call that will run"). The diff and
     the path come from the ask's own call (`row.call`), never from another row.
AC3. Diff view: added lines and removed lines carry their own class and a tinted background
     (frame `.dl.add`, `.dl.del`), and keep their screen-reader prefix. Unchanged lines within 3
     lines of a change are shown; any other run of unchanged lines becomes one line
     "⋯ n unchanged lines" (n the count; "⋯ 1 unchanged line" for one) with the frame's `.gap`
     look. A diff whose old text is null (a new file) shows every line as added. Test with a
     diff of 20 unchanged lines around 2 changes: the folded count equals 20 minus the context shown.
AC4. Ask bar, in DOM and visual order: the question ("Allow this edit?" for kind edit,
     "Allow this command?" for execute, "Allow this call?" otherwise), Deny… (quiet button,
     left), Allow `<reach>` this session (only with a reach, the reach verbatim), Allow once
     (primary, right, still `data-ask-first`). Deny… opens the frame's deny row (label "Tell the
     agent why", input, Cancel, Deny); Esc in the field and Cancel close it and return focus to
     Deny…. Answers are unchanged (same `actions.answer` calls).
AC5. "Thought for n s" and "Explored · …" fold buttons begin with a chevron `svg` (aria-hidden)
     that turns 90° when open (`aria-expanded` true), as the frame's `.foldbtn .chev`; the
     Explored button also has the search icon. Their accessible names stay exactly
     "Thought for n s" and "Explored · 3 reads, 1 search".
AC6. The fake story's second edit (`e2`, the open ask) carries a diff long enough to fold (at
     least 10 unchanged lines between two changes), so the played page shows a folded run.
     Nothing else in the story's outcome changes (one open ask, Needs you (1), plan 1 of 3).
AC7. Styles follow the frame's card, chead, badge, diff and askbar rules (radii per TECHNICAL
     18.4: cards 12–14 px, buttons 9 px, 36 px buttons); light and dark tokens from the page.
     `npm test` and `npm run typecheck` pass, and `ui/` is rebuilt (`npm run build`) so
     `test/build.test.ts` passes.
