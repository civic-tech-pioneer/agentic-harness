## Goal

A session allow never covers more than the ask the participant answered.
After this task `broker::reach` offers no reach (so no session allow) for
`Task`, `Skill`, `WebFetch`, `WebSearch` or any tool it does not name: only
the file tools (unchanged), `Bash` (below), `TodoWrite` and
`mcp__watane__<tool>` get one. A `Bash` reach also pins `timeout` and
`run_in_background`, so an allow given for `ls` does not answer `ls` run in
the background or with another timeout.

The rule (TECHNICAL 9.6, "As built (S31)", as edited by the foreman for S33;
quoted):

> for `Bash` `Bash(<command>)`, the exact command, only when that rule
> passes the 4.1 allow grammar, the command has no `:`, and the input has
> no key but `command`, `description`, `timeout` and `run_in_background`
> (so `dangerouslyDisableSandbox` always goes to the owner; S31-fix1) (the
> Waiting item "session allow on `Bash`", option (a)); then, when the
> input has them, ` timeout=<n>` (`timeout` a JSON integer from 0 to
> 2^64-1, written in decimal) and ` run_in_background=<true|false>` (a
> JSON boolean), in that order, each after one space; any other value of
> either gives no reach. So an absent key and a key with Claude's default
> value are different reaches, and `description` is never part of it
> (S33). `TodoWrite` and `mcp__watane__<tool>` (a name that passes the
> 4.1 rule grammar) get their name; every other tool, `Task`, `Skill`,
> `WebFetch`, `WebSearch` and any name not listed here among them, gets
> none (fail closed: a tool added to an allowlist later has no session
> allow until this list names it).

> An ask matches an allow when its `reach` equals the allow's, byte for
> byte (so a `Bash` allow holds only that exact command with the same
> `timeout` and `run_in_background`; ...).

Matching stays byte equality in `sessions.rs`; only the reach changes.

## Acceptance

AC1. Unit (`tests/it/broker.rs`): `reach("alice", None, "ask", t, &json!({}))`
is `None` for `t` in `Task`, `Skill`, `WebFetch`, `WebSearch`, `Agent`,
`MultiEdit`, `KillShell`, `BashOutput`, `mcp__other__x`, `mcp__watane__`
(empty tool part); it is `Some("TodoWrite")` for `TodoWrite` and
`Some("mcp__watane__send")` for `mcp__watane__send`.
AC2. Unit: `Bash` with `{"command":"ls"}` -> `Bash(ls)`; with
`{"command":"ls","description":"d"}` -> `Bash(ls)`; with `"timeout":5` ->
`Bash(ls) timeout=5`; with `"run_in_background":true` ->
`Bash(ls) run_in_background=true`; with `"run_in_background":false` ->
`Bash(ls) run_in_background=false`; with both and a description ->
`Bash(ls) timeout=5 run_in_background=true` (that order, whatever the key
order in the input).
AC3. Unit: `Bash` with `"timeout"` of `-1`, `1.5`, `"5"`, `null`, `true`, or
`"run_in_background"` of `"true"`, `1`, `null` -> no reach. A `timeout` of
`0` and of `18446744073709551615` give `timeout=0` and
`timeout=18446744073709551615`.

as the existing tests do): the owner answers `{"allow":true,"for":"session"}`
to a `Bash` ask `{"command":"npm test"}`; a later ask

`"timeout":600000` each open for the owner (not answered `session-allow`); a
later `{"command":"npm test","description":"other"}` is answered

AC5. Through the kernel: a `WebFetch` ask (and a `Task` ask) stores no

`{field: "decision"}` as for any ask with no reach (as `allows`/`broker.rs`
`ac7_an_ask_with_no_reach_refuses_for_session` does); a plain
`{"allow":true}` still works.
AC6. The HELD attacks stay held: every test in `adv_s31.rs`, `broker.rs`,
`allows.rs` passes, with only the changes listed below.
AC7. `cargo test`, `cargo clippy --all-targets -- -D warnings`,
