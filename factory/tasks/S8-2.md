## Goal

The Responses adapter in `kernel/src/adapters/responses.rs`: feed it one Responses streaming
event (as the host's HTTPS stream splits it, parsed JSON) or one tool job's output, and it
returns the same `Out`s as the Claude adapter (S8-1) for the three Responses rows of 9.8 and
for "anything else", never an error. It is pure and stateless: a job output comes with its
`function_call` item, so nothing is kept between calls. The OpenAI loop (9.5: requests, repair,
`response.completed`, errors) is a later slice; it calls this adapter.

## Acceptance

AC1. Golden fixtures under `kernel/tests/fixtures/adapters/responses/`, one per Responses row
     of 9.8 (`response.output_text.delta`; `function_call` items; `reasoning` summaries) plus
     `unknown.json`, in S8-1's fixture format with inputs `{"at", "event": <JSON>}` and
     `{"at", "job": {"call": <function_call item>, "output": "<text>", "ok": <bool>}}`; S8-1's
     runner gains the `responses/` branch, and its row check now covers all 12 rows of 9.8.
     Events are realistic Responses API streaming events (`type`, `sequence_number`,
     `item_id`, `output_index`, ...).
AC2. `response.output_text.delta` -> `agent_message_chunk` with the delta, no entry.
     `response.output_item.done` with an item of type `message` (role `assistant`) -> one `Out`
     with `agent_message_chunk` holding the whole text of its `output_text` parts and entry
     `message` (body `{"role":"agent","content":[…]}`, no `uuid`), as the Claude row (S8-1 AC3).
     A `refusal` part is text content too.
AC3. `response.reasoning_summary_text.delta` -> `agent_thought_chunk` with the delta. No entry.
     A `reasoning` item done gives nothing (its `encrypted_content` belongs to the wire
     history, 9.5, never to an update or entry).
AC4. `response.output_item.done` with an item of type `function_call` -> `tool_call`,
     `toolCallId` = the item's `call_id`, `title` = `name`, `status` `pending`, `rawInput` = the
     `arguments` parsed as JSON (the string itself when it does not parse). A job input ->
     `tool_call_update` (`completed` when `ok`, else `failed`) with the output as text content,
     and a `tool` entry with the finished call as S8-1 AC6 builds it, cut with S8-1's
     `cut_output`.
AC5. Known events with no row give nothing: `response.created`, `response.in_progress`,
     `response.completed`, `response.failed`, `response.incomplete`, `error` (the loop, 9.5,
     reads these), `response.output_item.added`, `response.content_part.added`/`.done`,
     `response.output_text.done`, `response.reasoning_summary_part.added`/`.done`,
     `response.reasoning_summary_text.done`, `response.function_call_arguments.delta`/`.done`.
     Any other event, an event without a string `type`, or one whose known type has fields of
     the wrong type, gives one `unknown` entry with the event as `raw`. A test feeds 1 000
     random JSON values and checks each returns `Out`s without a panic.
AC6. Pure and stateless: no `std::fs`, `std::time`, `std::env`, network, global state (S8-1's
     grep test covers this file); `cargo test` and `cargo clippy --all-targets -- -D warnings`
     pass in `kernel/`.

## Interface

Takes from S8-1, unchanged: `Out`, `Entry`, `Kind`, `unknown`, `cut_output` in
`kernel/src/adapters/mod.rs`, and the fixture format and runner of `kernel/tests/it/adapters.rs`.

Provides:
```rust
// kernel/src/adapters/responses.rs
pub fn event(event: &Value, at: u64) -> Vec<Out>;
pub fn job_output(call: &Value, output: &str, ok: bool, at: u64) -> Vec<Out>;  // call: the function_call item
```
