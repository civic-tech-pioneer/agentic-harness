## Goal

A Claude session that sits idle for 10 minutes gives its provider stream back
(9.5 "Slots", 9.3 "Deadlines and the session timer"): when its turn ends idle
the kernel sets its `idle` deadline and its one session timer `s/<id>`; a
turn that starts before then removes the deadline; when the timer fires, the
kernel cancels the provider stream and frees its slot, so the next `say`
resumes the Claude session (S26-2 AC6). Session timers are counted (240
kernel-wide, 120 per owner); a session that needs a timer at a cap releases
its stream at once instead of waiting.

## Acceptance

AC1. **Set.** A Claude session whose turn moves into `idle {..}` (any stop:
provider `Turn`, `Out.idle`, `interrupt`, `cancel` excluded since it
releases at once, a quota stop) while it holds a live provider stream gets
the deadline `{what: "idle", at: now + 600000}` in `rec.deadlines` (replacing
an earlier `idle` one), and the host timer `s/<id>` is set
(`Host::timer_after("s/<id>", at - now)`) to the earliest deadline of the
session. A session that had no timer before increments `slots.timers` and the
owner's timer count (`quota/<owner>`, new `Usage` field `timers: u32`, not
boot-tagged: timers survive a restart, 9.3). A turn that ends and starts the
next queued input in the same call sets no deadline.

AC2. **Cancelled by a turn.** A call that starts a turn on the session
(`say`, an `interrupt` replacement, a queued input) removes the `idle`
deadline; with no deadline left it calls `Host::timer_cancel("s/<id>")` and
decrements both timer counts; with others left it re-arms the timer for the
earliest. A `say` that only queues leaves the deadline (the turn is active
then anyway).

AC3. **Fired.** New handling in `Kernel::timer(id)` for `id` starting with
`s/`: it runs R1 (`begin`) as today, loads the session (R6 first when
stale), handles every deadline with `at <= now`: `idle` releases the
session's live provider stream (`Host::cancel_stream(t)`, then the S26-2
release helper: `stream/t`, `streams`, both slot counts), others are left
for their stages (D) untouched. Then it re-arms `s/<id>` for the earliest
remaining deadline, or (none left) frees the timer (counts decremented; no
`timer_cancel` needed for the timer that fired). A firing for a deleted
session, or with no due deadline, changes nothing but the timer count when
the record says it holds none. A firing is never an error.

AC4. **Next say resumes.** After the release, `say` opens a new provider
stream (`Host::open_stream`) and sends `Request::Turn { resume: true }`;
with `persist: false` in the profile, `resume: false` (case 52).

AC5. **Timer caps.** When `slots.timers` is 240, or the owner's count is 120
(`Limits` fields `timers: u32 = 240`, `owner_timers: u32 = 120`, settable),
and a session without a timer would need one for `idle`: no timer and no
deadline; the provider stream is released at once in that call
(`cancel_stream` and the release). Nothing waits for a timer slot.

AC6. **Cancel and delete.** `cancel` and `delete` remove the session's
deadlines, cancel `s/<id>` if it was set and decrement both counts (delete:
the counts only drop when the record held a deadline).

AC7. **Restart.** Timer counts are not zeroed by R1 (as today). An `idle`
deadline of a session whose stream was dropped as stale by R4 fires and
finds no live provider stream: it releases nothing and frees the timer.

AC8. **Counts.** After any sequence of the above, `slots.timers` equals the
number of sessions with a non-empty `deadlines`, and each owner's count those
of its sessions (a test checks this from `MemState::entries()`).

AC9. **A failed opening call leaks no stream.** When `start`, `say` or an
`interrupt` replacement has called `Host::open_stream()` and then fails (a
`quota` from `finish` past the reserve, a `too-large` from `seal` or
`key_put`), it calls `Host::cancel_stream(t)` for that stream before it
returns the error, and sends no request (foreman decision, S26-2 validator
note: spec 7 rolls back the call's writes and requests, but the host stream
opened in it would hold a `claude` slot of the host). Test: a `start` that
fails `quota` past the reserve logs `Open {t}` then `CancelStream {t}`.

## Interface

Takes from S26-2 (fixed): `Host::open_stream`, `Host::cancel_stream`,
`HostCall::CancelStream`, `Kernel::provider_item`, the release helper,
`Usage.provider`, `Limits.provider`/`owner_provider`.
Adds: `Usage.timers: u32` (serde default 0), `Limits.timers`,
`Limits.owner_timers`; the deadline `what` string `idle`; the timer id
`s/<session id>`.
