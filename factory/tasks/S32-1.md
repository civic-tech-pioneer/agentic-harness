## Goal

The kernel crate speaks watane's host 19 exactly (the S32 seam audit), and it has the stage A
probe. After this task the crate's `Host` trait has host 19's shapes: an owner stream comes from a
fallible `streams.open()`, a provider stream only from the provider's `start` (stage A: none is
linked, so a Claude `start` is refused and writes nothing), `push` fails with host 19's
`stream-error`, `close` passes the `outcome` variant, timers are never asked for more than 30 days,
and an item call takes a numbered batch and drops items at or below the last `seq` it took (case
7). And `Kernel::probe_start` plus the session timer write a probe session's numbered entries,
pushed live to its owner stream (TECHNICAL 9.9), so a page can watch them arrive and reattach
without a miss or a double.

## Acceptance

AC1. `Host` (kernel/src/sessions.rs) has exactly the methods of `## Interface`; `FakeHost`
     implements them and records each in `calls`. `cargo test`, `cargo clippy --all-targets -- -D
     warnings` and `cargo fmt --check` pass in `kernel/`.
AC2. Owner stream open fails: with `FakeHost.open_error = Some(StreamError::NotYours)`, `attach`
     returns `Err(KernelError::Backend(m))` where `m` starts with `not-yours`, and state is
     unchanged (no `stream/`, no `live/`, record `streams` unchanged; compare a state snapshot).
     Same for `Full` (`full`).
AC3. No provider: with `FakeHost.no_provider = true`, `start` of a Claude profile returns
     `Err(KernelError::Backend("no Claude Code provider is linked"))` and state is unchanged (no
     session record, no owner page, no client key, quota unchanged). With a provider (default),
     `start` records `HostCall::StartProvider { launch, input }` and the session's provider stream
     is the id it returned (the existing start/attach tests keep their stream ids).
AC4. `push` failing `UnknownStream` (or `NotYours`, `TooLarge`) on the live owner stream: the kernel
     drops its live stream (no `stream/<o>`, no `live/<session>`, not in `streams`), closes nothing
     (no `HostCall::Close` for it), and the entry is still stored; the next `attach` after the last
     index replays it once.
AC5. `close` passes `Outcome::{Closed, Replaced, Lagging}`; every place that passed a text passes the
     variant (`HostCall::Close { stream, outcome: Outcome }`).
AC6. A deadline more than 30 days out arms `TimerAfter { delay_ms: MAX_TIMER_MS }`; that firing
     finds nothing due and arms the rest (again at most `MAX_TIMER_MS`). No `TimerAfter` in any
     test has `delay_ms > MAX_TIMER_MS`.
AC7. Case 7 (kernel part): `provider_batch(stream, items)` with items `seq` 1..3 takes them; the
     same batch again changes no state and pushes nothing (returns `Taken`); a batch `seq` 2..5
     takes only 4 and 5. Items are taken in `seq` order; the last taken `seq` is kept in the
     stream's `stream/<id>` key (one write per batch). A batch where an item defers returns
     `Defer` and its own `seq` is not recorded as taken.
AC8. Probe start: `probe_start(owner, key, 3, 1000)` returns a session id; the record has backend
     `probe`, title `Numbered items`, turn `idle`, deadline `{what: "probe", at: now+1000}` and the
     timer `s/<id>` armed; a repeat with the same key returns the same id and changes nothing;
     `count` 0 or 1001 and `every-ms` 99 or 60001 are `refused` naming `count` / `every-ms`; it
     counts one session against the owner (the owner's 9.3 cap refuses past it).
AC9. Probe firing: with an owner stream attached, three firings (clock advanced each time) push
     three `entry` items with `i` 1, 2, 3 and text `Item 1 of 3` .. `Item 3 of 3`; the third arms
     no further timer. A reattach `attach(session, after: 2)` replays only entry 3; `after: 0`
     replays 1..3 once each; `read` returns them too. A firing with the owner stream full stores
     the entry and drops the live stream `lagging`; `attach(after: <last shown>)` then replays
     exactly the missing entries.
AC10. On a probe session `say`, `answer`, `interrupt`, `queued`, `unqueue` and `take-back` are
     refused `backend("a probe session takes no input")`; `cancel` drops the `probe` deadline (no
     more entries after it); `list`, `rename`, `delete` work as for any session; another owner's
     calls get `unknown-session` as for any session.

## Interface

Provides to S32-2 (exact; S32-2 implements `Host` over the WASM imports):
```rust
pub trait Host {
    fn boot(&mut self) -> u64;                 // unchanged
    fn now(&mut self) -> u64;
    fn new_id(&mut self) -> String;
    fn timer_after(&mut self, id: &str, delay_ms: u64);   // the kernel never passes > MAX_TIMER_MS
    fn timer_cancel(&mut self, id: &str);
    fn request(&mut self, r: Request);
    /// `streams.open()`: a new owner stream (9.4).
    fn open_stream(&mut self) -> Result<String, StreamError>;
    /// The provider's `start` (2.2): the provider stream of a new Claude session; `Err(cause)`
    /// when none is linked (stage A).
    fn start_provider(&mut self, launch: &str, input: &str) -> Result<String, String>;
    fn cancel_stream(&mut self, stream: &str);
    fn push(&mut self, stream: &str, value: Value) -> Result<(), StreamError>;
    fn close_stream(&mut self, stream: &str, outcome: Outcome);
    fn resume_stream(&mut self, stream: &str);
}
pub enum StreamError { NotYours, UnknownStream, Full, TooLarge }   // + fn code(&self) -> &'static str: "not-yours", ...
pub enum Outcome { Closed, Replaced, Lagging }
pub enum SinkOutcome { Taken, Defer }      // replaces `Item { Done, Defer }`
pub const MAX_TIMER_MS: u64 = 30 * 24 * 60 * 60 * 1000;
impl Kernel<S, H> {
    pub fn provider_batch(&mut self, stream: &str, items: Vec<(u64, ProviderEvent)>) -> Result<Called<SinkOutcome>, KernelError>;
    pub fn probe_start(&mut self, caller: &str, key: &str, count: u32, every_ms: u32) -> Result<Called<String>, KernelError>;
}
```
`launch` passed to `start_provider`: the session's profile JSON until stage B builds 4.1's launch
document; `input`: the start's input. `FakeHost` gains `open_error: Option<StreamError>`,
`no_provider: bool`, `gone: BTreeSet<String>` (push fails `UnknownStream`), keeps `full`, and one
counter for `open_stream` and `start_provider` ids (`t1`, `t2`, ... as today). `HostCall` gains
`StartProvider { launch, input }`; `Close.outcome` is `Outcome`. All re-exported from `lib.rs`.
`provider_item` may stay as the one-item form used by tests, returning `SinkOutcome`.

order. Any other existing assertion that has to change is a question: stop and say so.
