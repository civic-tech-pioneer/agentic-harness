## Goal

Four things that felt wrong are right (S15 user-sim, S17): the status line names an ask's call
once ("Waiting for you · Edit s.ts", not "Edit Edit s.ts"); a decided card whose call never ran
shows the decision, not "Pending"; an open check that shares a card with an open ask shows that
it is checking; and a Claude tool call the page saw streaming before watane restarted shows as
ended once the turn is over (the kernel never closes it, TECHNICAL 9.3 R4), not as running.

## Acceptance

AC1. Status subject. While `waiting`, the status word's subject is the card's own name for the
     first open ask: the kind as a word and `askArg(ask.input)`, else the ask call's `title`
     (exactly what the card header shows, one function shared by both). "Waiting for you · Edit
     src/s.ts" for an Edit ask on `src/s.ts` whose title is "Edit s.ts"; "Waiting for you · Other
     other" never appears: an `other` ask with no argument shows its title alone ("Waiting for
     you · other" only if the title is "other"; no kind word before a title that already starts
     with that kind, case-insensitive).
AC2. Decided, never ran. A card whose shown entry (ask or check) is decided and whose call's
     status is still `pending` (no later status from the stream) shows the decision as its tag:
     "Allowed" (`b-ok`), "Denied" (`b-bad`), "No objection" (`b-off`), never "Pending". A
     later status from the stream (`in_progress`, `completed`, `failed`) shows as today.
AC3. Check with an ask. When a card shows an open ask and the same call has an open check, the
     card shows a second tag "Checking" (`b-off`, after "Waiting for you"), and the ask bar as
     today; when the check is decided, that tag goes. The ask still decides the card's call and
     its bar (S15's rule: first open ask, then a check). The reducer exposes this on the tool row
     (`checking?: true`, AC interface) and nothing else changes in which entry the card shows.
AC4. Ended after restart. When the turn becomes `unknown`, `resume-lost` or `idle` (any kind), a
     tool call that is still `pending` or `in_progress` and has no open ask or check shows the tag
     "Ended" (`b-off`) and no running look; the call's own data is not rewritten (a later `tool`
     entry for it, should one come, shows its status as usual). A call with an open ask or check
     is not marked. The status line's running word never names an ended call (it is not running).
AC5. Tests at the lowest level: reducer tests for AC3 and AC4 (on the S10 wire, as the fixtures of
     `kit/parts_S15.test.ts` and `kit/s15_1.test.tsx` are written), view tests for AC1-AC4.
AC6. The held cases pass with their assertions unchanged: `console/kit/adv_S9.test.tsx`,
     `console/kit/adv_S9_diff.test.tsx`, `console/kit/adv_S15.test.tsx`,
     `console/kit/regress_S15_fix1_entry_call.test.ts`,
     `console/kit/regress_S15_fix2_bar_resets.test.tsx`, `console/kit/adv_S4.test.tsx`, and the
