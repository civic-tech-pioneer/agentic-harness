## Goal

After this task the console's transcript and status line exist as React views in `console/kit/`,
rendered through assistant-ui: Alice's message as a quiet panel, thinking that is open while it
streams and then folds to "Thought for n s", reads and searches folded to one "Explored · n
reads, m searches" line, an edit as a card with its diff, a failed call as an open card, an open
ask inside its tool card with the ask bar, decision lines, the turn footer, a muted line for an
unknown event, and the status line of 18.5 with one shape per state. Each is proven by a
component test from scripted wire messages (the fake of S4-1), not by a browser.

## Acceptance

Each test builds a `SessionView` by feeding `reduce` (S4-1) wire messages, renders the view with
Testing Library in jsdom, and asserts on roles and text.

AC1. `user` row: a panel with the text, aligned right (a class or data attribute the CSS of
     S4-3 places right; assert the attribute).
AC2. `thought` row: while `streaming`, the text "Thinking…" and the thought are shown open; once
     not streaming, a closed disclosure "Thought for n s" (n from `seconds`) that opens on click
     and by keyboard (Enter/Space).
AC3. `explored` row: one closed disclosure "Explored · 3 reads, 1 search" (singular and plural
     right, a zero part left out); opening it lists each call's title.
AC4. `tool` row of an edit: a card with the tool name, its argument (the path or title), the
     diff (removed and added lines marked, by text prefix or role, not by colour alone) and the
     status in words. An `execute` call shows its output as text, escaped (a test feeds
     `<img src=x onerror=alert(1)>` and an ANSI colour sequence and finds no `img` element and no
     raw escape byte). A `failed` call's card is open; a completed non-failed one may be closed.
AC5. Open ask: its tool card shows every argument (`input`) and, for an edit, the diff, plus the
     ask bar: "Allow once" (primary), "Allow <reach> this session" (reach from the input: e.g.
     "edits in ~/Notes"), "Deny…". "Deny…" opens a reason field with "Deny" and "Cancel"; Esc in
     that field closes it without calling anything. Each button calls `actions.answer` with the
     right decision (`{outcome:"allow"}`, `{outcome:"allow", for:"session"}`,
     `{outcome:"deny", reason}`).
AC6. `decision` row: one line naming who, what, and the reason when there is one.
AC7. `footer` row: "Completed in 9 s · 2 tools · 18k tokens" (tokens left out when unknown).
AC8. `unknown` row: a muted line "An event this console does not know", the raw JSON shown on
     demand (a button), escaped.
AC9. `StatusLine`: one test per row of 18.5: the word (with its subject where 18.5 names one:
     the file of the running read or edit), a shape element with a distinct `data-shape`
     (`dot`, `square`, `diamond`, `bars`, `ring`, `dashed-ring`, `triangle`) and an accessible
     name, the elapsed time for running (from `since` and `now`), the time left to `expiresAt`
     for waiting, "Paused until hh:mm", and the act it names (Stop with "Esc", Needs you,
     Resume now, Try again, Continue, Continue from a summary) as a button. Only the word and
     its subject are inside the `role="status"` live region; the clock is `aria-hidden`. With
     `stopping` true it shows "Stopping…" until the turn is idle.
AC10. A streaming `agent` row has `aria-busy="true"`; a `writing` row with no text shows
     "Writing…"; a finished one has no `aria-busy`.
AC11. The rows render inside assistant-ui's thread (`AssistantRuntimeProvider` with
     `useExternalStoreRuntime`, messages converted from `SessionView.rows`, message ids from the
     row `key`); a test renders the story's end view (S4-1 `story`) through `ThreadProvider` and
     `Transcript` and finds each row kind once, none doubled.

Decision of this slice: assistant-ui's own ACP adapter is private and not on npm, so "its ACP
runtime" of 18.2 is its External-store runtime fed by S4-1's reducer. Use only parts of
`@assistant-ui/react` that need no iframe, no network and no `eval`. Shiki is not needed by any
acceptance criterion here: leave it out (no code highlighting in this slice). Program output:
anser with escaping (`anser.escapeForHtml` before `ansiToHtml`), or strip ANSI to plain text;
never `dangerouslySetInnerHTML` with unescaped input. The diff view: compute line diffs with a
small dependency (`diff`) or by hand; no `eval`.

Do not edit `design/` (slice S2 owns it now). If a rule there is unclear, follow this brief and
say so under `QUESTIONS`.
