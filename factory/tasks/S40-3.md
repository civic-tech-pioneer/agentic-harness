## Goal
An OpenAI session runs in the kernel: `start` and `say` on a profile with `backend: "openai"` make
the kernel send a Responses request through `https-stream` (account `openai`), the reply's text and
reasoning stream to the owner as the Claude backend's do (one event format), the finished response
is stored in the wire history, the owner gets a `usage` item after each step (the context meter), a
usage limit pauses the session until its reset time and the session goes on by itself when the
timer fires, a retryable error retries with backoff, and `interrupt`, `cancel`, `delete` and a
restart treat the loop as 9.5 says. Tool calls are handed to one function that S40-4 fills; in this
task each call is answered `aborted` so the loop is whole.

## Acceptance
AC1 `start` with an OpenAI profile (FakeHost) makes exactly one `HostCall::HttpsStart` whose request JSON is `{"url":"https://api.openai.com/v1/responses","method":"POST","headers":{"content-type":"application/json","accept":"text/event-stream"},"body":<S40-1's body>,"account":"openai","idle-s":90}` and no other field; its body's `input` holds the input as one user message; `stream/<id>` of the returned stream has kind `request`; the turn is `running`; `slots.request` is 1. No `StartProvider` call happens. `start` refused by the host (`https_start` returns `Err`) writes nothing and returns `backend(<cause>)`.
AC2 Items on that stream (through `provider_lines`, as the WASM wrapper delivers them): the head, then SSE events of dev 18.3's shapes (`Delta`, `Completed`), give the owner the same `_meta`-free ACP updates and entries the Responses adapter (`kernel/src/adapters/responses.rs`) makes, the turn ends `idle {completed}` with `tokens` set, the response's output items are appended to the wire, and one `{"type":"usage","context-used":<input_tokens>,"context-window":272000,"compact-at":200000}` push follows each completed step. The request slot is freed at the stream's `ended`.
AC3 (case 2, loop part) A `say` after an idle turn sends a second request whose `input` extends the first body's `input` (prefix byte-equal) and whose `instructions` are byte-equal; `instructions` are compiled once at `start` (the profile's `system-prompt`, then the overlay's `system-prompt-append`) and kept in `loop/<id>`.
AC4 (case 3) A stream that ends `closed` without `response.completed` ends the turn `idle {failed {error: "the response ended before it completed"}}`; nothing of that response is appended to the wire.
AC5 (case 4) A 429 head with the usage-limit body (dev 18.3 `UsageLimit {resets_in_s: 60}`), and in a second test a `response.failed` with `usage_limit_reached`, each give exactly one turn change to `paused {until}` (until = now + 60 000 for the first, absent for the second), a `resume` deadline at `until` on the session timer `s/<id>` for the first; when that timer fires the loop sends the request again (same body) and the turn is `running`; at the next completed response it ends `idle {completed}`. `say` on the timed pause queues; on the untimed pause it resumes (9.3).
AC6 Retry: a 500 head, and an `ended` `idle-timeout`, each set a `retry` deadline at now + `backoff_ms(attempt)`, the loop is `retrying {attempt}`, the turn stays `running`; the timer's firing sends the request again; after 6 failed attempts the turn is `paused` with no `until` (9.3), the error text kept in the loop state as `last-error` (9.3's turn JSON does not change); the next `say` resumes it. A 400 head ends the turn `idle {failed {error: <Fatal message>}}`.
AC7 `interrupt` while `requesting` cancels the request stream (`HostCall::CancelStream`), frees its slot in the same call, and ends the turn `idle {interrupted}`; with a replacement it starts the next request. `cancel` does the same and ends nothing more; `delete` also deletes `loop/<id>` and every `wire/<id>/<n>`.
AC8 Request slots (9.5 Slots): with 8 requests in flight (two owners, 4 each), a ninth session's `start` succeeds, its loop is `ready`, it waits in the FIFO (`slots/wait/<n>`), and it is sent in the same call that frees a slot (an `ended` of another request stream); an owner at 4 waits while another owner's work starts.
AC9 Restart (9.5 "After a restart", R4): an OpenAI session `requesting` at the restart goes to `ready` and takes a request slot or waits; `retrying` keeps its deadline; `paused` is unchanged; no OpenAI session becomes `unknown`.
AC10 Over the body budget with nothing left to trim (`Err(BodyTooLarge)`): the turn ends `idle {failed {error: "too-large"}}` and the next `say` restarts from a summary (`Wire::restart_from_summary`, the summary being the text of the last assistant message entries of the transcript, at most 32 KiB, newest kept) and sends it.
AC11 The calls of a completed response go to `fn openai_calls(&mut self, rec, ls, calls: Vec<Value>, work)`; in this task it appends one `function_call_output` `"aborted"` per call and goes `ready` (a next request); S40-4 replaces its body.

## Interface
Takes `crate::openai::wire` (S40-1) and `crate::openai::answer` (S40-2) as their briefs fix them.
Provides, in `kernel/src/sessions.rs`, these additions to the `Host` trait (and to `FakeHost`, which logs them as the new `HostCall` variants below and answers stream ids `t<n>` from `next_stream`):
```rust
/// `https-stream.start` (2.1, 5): the request's stream, or the host's `start-error` as text.
fn https_start(&mut self, request: &str) -> Result<String, String>;
/// `agent-tools` (6): used by S40-4.
fn tools_open(&mut self, toolsets: &[String]) -> Result<String, String>;
fn tools_describe(&mut self, handle: &str) -> Result<Vec<Tool>, String>;
fn tools_call(&mut self, handle: &str, key: &str, tool: &str, args: &str) -> Result<String, String>;
fn tools_close(&mut self, handle: &str);
#[derive(Debug, Clone, PartialEq, Eq)] pub struct Tool { pub name: String, pub description: String, pub input_schema: String, pub parallel: bool, pub idempotent: bool }
// HostCall gains: HttpsStart { request: String }, ToolsOpen { toolsets: Vec<String> }, ToolsDescribe { handle: String }, ToolsCall { handle: String, key: String, tool: String, args: String }, ToolsClose { handle: String }
// FakeHost gains: pub https_error: Option<String>, pub tools: Vec<Tool>, pub tools_error: Option<String>, and answers tools_open with "h<n>".
```

Items of `request` streams arrive through the existing `provider_lines`/`provider_ended_with` (the WASM wrapper does not change its routing): route by `stream/<id>`'s `kind`. Make `may_use` and `profile_json` of `Kernel` `pub(crate)` (S40-5 uses them). Put the loop's code in `kernel/src/openai/run.rs` (an `impl<S: State, H: Host> Kernel<S, H>` block; `pub mod run;` in `openai/mod.rs`), with the loop state `LoopState` there, `#[serde(flatten)] wire: Wire` inside; keep the changes to `sessions.rs` to the hooks that route to it.
