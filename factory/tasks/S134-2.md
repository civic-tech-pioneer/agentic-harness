## Goal

Every turn stops at its limits (sketch outcome 3). An OpenAI turn counts its completed model steps,
its tool-error streak and its tokens, and stops `idle {stopped {limit: max-turns | max-tool-errors |
max-tokens}}` as TECHNICAL 9.7 "Limits" says, with at most one tool-free summary step at
`max-turns`, and fails `usage-unavailable` when a token cap meets a response without token counts. A
Claude turn whose `result` has `subtype: "error_max_turns"` ends `stopped {limit: max-turns}` at its
idle. The Claude end-of-turn usage sample or meter clear of 9.7 "Usage" is pushed.

## Acceptance

AC1. OpenAI profile `max-turns: 2`: step 1 calls a tool, step 2 calls a tool -> step 2's calls get
     `aborted` outputs (no job starts), one more request is sent with no `tools` (and no `task`
     later), its text completes -> `idle {stopped {limit: max-turns}}`. A retry (5xx) of that summary
     request is again tool-free; a summary response that calls a tool runs nothing.
AC2. `max-turns: 1` and a final text answer on step 1 -> `idle {completed}`, no extra request.
AC3. `max-tool-errors: 2`: two failed outputs in a row (a job `err`, a profile denial) -> the turn
     stops `stopped {limit: max-tool-errors}`, other open calls and pending calls get `aborted` (as
     interrupt cleanup, 9.5), those aborts do not count; a success between two failures resets the
     streak (no stop).
AC4. `max-tokens: 100`: a response with 60+50 tokens that calls tools -> no job starts, its calls
     get `aborted`, `stopped {limit: max-tokens}`; a final text answer crossing the cap also ends
     `stopped {limit: max-tokens}`; at `max-turns` and `max-tokens` together the token cap wins.
AC5. `max-tokens` set and `response.completed` without `usage` -> `idle {failed {error:
     "usage-unavailable"}}`, no job starts. Without `max-tokens` the same response goes on as today.
AC6. Counters reset at each input that begins a turn (a second `say` after a stop gets the full
     budget again); an ask, a retry and a usage-limit pause inside the turn keep them.
     `loop/<id>` carries `turn-steps`, `tool-errors-in-a-row` and `summary` (9.5 State).
AC7. Claude: a provider `result` with `subtype: "error_max_turns"` then idle -> the turn ends
     `idle {stopped {limit: max-turns}}` (turn entry and push); a `result` of an interrupted turn
     arriving late does not end the replacement turn (existing `owed-idles` rule).
AC8. Claude usage (9.7 "Usage"): a `result` with `num_turns: 1` and exactly one model in
     `model_usage_since_last_result` with a positive `contextWindow` pushes `{"type":"usage",
     "context-used": inputTokens+cacheReadInputTokens+cacheCreationInputTokens, "context-window":
     <contextWindow>}` (no `compact-at`); any other `result` pushes the clear
     `{"type":"usage","context-used":null,"context-window":null}`; attach replays only a current
     sample (none after a clear).

## Interface

Provides (fixed; S134-4 builds on these):
- `LoopState` (kernel/src/openai/run.rs) gains `turn_steps: u32`, `tool_errors_in_a_row: u32`,
  `summary: bool`, serialized kebab-case and skipped when zero/false, reset where `turn_tokens` is.
- `pub(crate) fn count_output(&mut self, ls: &mut LoopState, ok: bool) -> bool` on the kernel in
  tools.rs, or the same logic inside `put_output`: every non-cleanup output updates the streak;
  returns whether `max-tool-errors` is reached. S134-4 calls `put_output(.., ok)` for `task` outputs
  with `ok = true` only for the `{"ok":…}` envelope; cleanup aborts pass through a path that does not
  count (name it in a doc comment).
- The policy's limits: `Policy` (tools.rs) gains `max_turns: Option<u32>`, `max_tool_errors:
  Option<u32>`, `max_tokens: Option<u64>`, compiled once in `loop_for` from profile + overlay.
- A request built with `ls.summary` true sends no `tools` field.
