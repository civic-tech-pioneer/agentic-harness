## Interface

Naming rule (write it once in 9.4): names ACP has keep ACP's spelling (`toolCallId`, `toolCall`,
`rawInput`, `sessionUpdate`); the kernel's own keys are kebab-case (`expires-at`, `context-used`).

A. `decision` (2.3), exactly one of `allow`, `deny`, `none`, its value `true`:
   `{"allow":true}`; `{"allow":true,"for":"session"}`; `{"allow":true,"input":{…}}` (a changed
   input, only for `AskUserQuestion` and `ExitPlanMode`, 4.5); `{"deny":true,"reason":"<text>"}`
   (`reason` optional, empty when absent); `{"none":true}` (a check only, 4.5). Any other shape,
   or `for`/`input`/`reason` with the wrong outcome: `refused` with one refusal
   `{field: "decision", reason}`. `answer`'s `ask` argument is the ask entry's `id` (the ask id
   of 9.3's deadlines), never the tool call id. A check (`kind: "check"`) is answered only by the
   checked provider (10); the owner's `answer` to it is refused, `{field: "ask"}`.
B. The wire (9.4). Every stream message is one JSON object:
   - an ACP v1 `SessionUpdate` (`{"sessionUpdate":…}`), with `_meta.watane.at` (ms, the kernel's
     clock when it adapted the line) on every live update and `_meta.watane.i` on the update that
     finishes an entry (`message`, `tool`);
   - `{"_meta":{"watane":{"type":"entry","entry":<entry>}}}` for an entry with no ACP form
     (`ask`, `allow`, `verdict`, `turn`, `compaction`, `unknown`, `part`), live and in replay; in
     replay every entry goes out this way (a client also accepts a bare entry object);
   - `{"_meta":{"watane":{"type":"synced","through":<i>,"writing":true?}}}`; `writing` is true when
     a message was being written at the attach (18.3 "Writing…"), absent otherwise;
   - right after `synced`, before any live update, `attach` pushes the current `turn` item, the
     `queue` item, the last `usage` item when there was one, and the turn's last `Plan` update
     when the turn has one;
   - `{"_meta":{"watane":{"type":"turn","state":<turn JSON, D>}}}`;
   - `{"_meta":{"watane":{"type":"queue","inputs":[{"n":<n>,"input":"<input JSON>"}]}}}`;
   - `{"_meta":{"watane":{"type":"usage","context-used":…,"context-window":…,"compact-at":…?}}}`.
   An ask goes out once, as its `entry` item; there is no separate `ask` update.
C. Entry bodies (9.4):
   - `message`: `{"role":"user"|"agent","content":[<ACP content blocks>],"thought":{"text","seconds"}?}`;
     `thought` on an agent message: the thinking of that step joined, `seconds` from its first to
     its last thought chunk's `at` (rounded). (So replay shows thinking; 9.8 has no entry for it.)
   - `tool`: an ACP ToolCall: `toolCallId`, `title`, `kind`?, `status`, `content`?, `locations`?,
     `rawInput`?, `rawOutput`? (output cut to 64 KiB, marked).
   - `ask`: `{"id":"<ask id>","kind":"ask"|"check","toolCallId":"<the call's own id>",
     "toolCall":<ACP ToolCall, its toolCallId the same, rawInput = input>,"input":<the full input>,
     "expires-at":<ms>,"reach":"<rule>"?}`; `reach` is the session allow an
     `{"allow":true,"for":"session"}` would add (9.6, e.g. `Edit(<workspace>/**)`), absent when
     none is offered (a check, an `agent:` owner). A decision is a later `ask` entry that repeats
     every field of the ask and adds `"decision":{"outcome":"allow"|"deny"|"none","by":"<who>",
     "for":"session"?,"reason":"<text>"?}`; `by` is `owner`, `session-allow`, `checked` (the
     checked provider), `kernel` (a kernel ask's expiry, `timers`, no owner stream, `cancel`) or
     `host` (a Claude ask the host resolved: `reason` is the host's `by`, `expired` or
     `cancelled`). Repeating the ask lets a page that starts at the decision show the card.
   - `allow`: `{"id":"<allow id>","reach":"<rule>","given":true|false,"by":"<who>"}`.
   - `verdict`: `{"on":"<ask id>"|"input","toolCallId":"<id>"?,"outcome":"safe"|"unsafe","reasons":[…],"by":"<provider>"}`
     (`toolCallId` when `on` is an ask).
   - `turn`: the turn JSON (D) without `activity`.
   - `compaction`: `{"tokens-before":<n>?}`. `unknown`: `{"raw":<the JSON value, or the line as a string>}`.
   - `part`: as now.
D. Turn JSON (9.3):
   `{"state":"running","since":<ms>,"activity":{"kind":"checking","on":"<ask id>"|"input"?}|{"kind":"compacting"}|{"kind":"consent","what":"<text>"}?}`;
   `{"state":"waiting","asks":["<ask id>",…],"expires-at":<ms, the earliest open ask's>}`;
   `{"state":"paused","until":<ms>?}` (`until` absent for a pause with no time, 9.3);
   `{"state":"idle","stop":{"kind":"completed"|"interrupted"}|{"kind":"stopped","limit":"<limit>"}|{"kind":"failed","error":"<error>"},"seconds":<n>?,"tools":<n>?,"tokens":<n>?}`
   (the turn's wall time in seconds, tool calls and tokens, for 18.3's footer);
   `{"state":"unknown"}`; `{"state":"resume-lost"}`.
