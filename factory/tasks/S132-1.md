## Goal

Specify a single contract for the stage F journey, child admission and lifecycle,
per-backend limits, usage reporting, and the console. Carry the findings through
the spec chain and leave a reviewable stage F acceptance and load target.

## Acceptance

1. AC1. Read AGT-J5 against both backends' tool and depth rules. The OpenAI root
   can start both named children, and an attempted grandchild or unnamed child
   is refused.
2. AC2. Compare a candidate against the effective parent at dispatch. A wider
   field gives a named refusal, and the owner and workspace rules preserve
   consent and visibility.
3. AC3. Follow a task through start, stop, replay and restart. Each started child
   has one stored link and each waiting call gets one terminal output.
4. AC4. Follow a turn on each backend through its limits and meter updates.
   The supported limits have explicit scope and stop reasons, and the stage
   D OpenAI meter remains specified.
5. AC5. Count requests and jobs in the F fixture under the existing caps.
   The console display, acceptance cases, and stage row trace the same contract.
