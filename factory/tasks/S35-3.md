## Goal

The unchecked Claude Code provider exists as a self-contained watane mod in `provider/` (until the
human answers R-B1, when a `git subtree split` makes it its own repository). Its `sessions.start`
lets only the kernel start Claude Code with the participant's `claude-code` grant: it checks the
caller, starts `claude` with the launch unchanged, says the input's text while it is still the
stream's consumer, hands the stream to the kernel, and answers `{stream, direct: true}`. Its other
functions answer `not-direct`. This decides the owner check of a security boundary (TECHNICAL 14,
"A mod in the middle gains no authority"): exactly one identity passes, `local/agent` in stage B
(10 "Unchecked", R-B3).

## Interface

Provides to S35-2 (fixed):
```wit
package mods:claude-code@0.1.0;

interface sessions {
  use watane:host/streams@0.1.0.{stream-id};
  use watane:host/claude-types@0.1.0.{start-error, session-error, decision};

  record started { %stream: stream-id, direct: bool }

  start: func(launch: string, input: string) -> result<started, start-error>;
  say: func(s: stream-id, content: string) -> result<_, session-error>;
  answer: func(s: stream-id, ask: string, d: decision) -> result<_, session-error>;
  interrupt: func(s: stream-id) -> result<_, session-error>;
  compact: func(s: stream-id) -> result<_, session-error>;
}
```
The mod's slug is `claude-code` (the package name), so the kernel's `watane-dev add ../../provider`
makes `wit/deps/claude-code/`.
