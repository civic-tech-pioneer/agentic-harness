Slice: S1 — a maker runs `python3 -I proto/claude-probes/probes.py subagent-slash loopback` on the Mac and sees, for the current `claude`, whether a subagent prompt that starts with `/` runs a skill the profile denies, and whether the shell grant's sandbox blocks a connection to loopback.

## Goal

`probes.py` gains two probes, `subagent-slash` (V26) and `loopback` (V27), each runnable alone by
its name and printing result lines through `record()` like the others. Each probe also proves it
really tested the question (a control case that must succeed, and a check that the model did what
was asked), so a "blocked" result can never come from a probe that did not try. This task writes
the probes only; the foreman runs them against the real `claude` afterwards (the implementer's
sandbox has no logged-in `claude`).

## Acceptance

AC1. `PROBES` has the keys `"subagent-slash"` and `"loopback"`; `python3 -I probes.py subagent-slash`
     runs only V26, `... loopback` only V27; an unknown name still records a crash line as today.
AC2. `probe_subagent_slash` (docstring starts `V26:`): a plugin skill `fruit` as in `probe_slash`
     (reply `PINEAPPLE`); the parent gets `--agents=` with one subagent `runner` (no
     `permissionMode`, tools `["Skill", "Read"]` for the control, see cases) and is told to start the
     `runner` subagent with a prompt of exactly `/watane-run:fruit` and to reply with what it returns.
     Cases, each its own `record` line:
     - control: `--tools=Agent,Task,Skill,Read`, no deny rule: expect the skill ran;
     - denied by rule: same tools plus `--disallowedTools=Skill(watane-run:fruit)`: expect not ran;
     - Skill not in `--tools` (`--tools=Agent,Task,Read`, subagent tools `["Read"]`): expect not ran.
     "Ran" means `PINEAPPLE` appears in a message with a `parent_tool_use_id` or in the Agent/Task
     tool result (not only in the parent's final text, which could be invented). Each line's detail
     names: whether an `Agent`/`Task` tool_use was sent with an `input.prompt` starting with `/`
     (`slash prompt sent=True/False`), `skill ran=`, and the first 80 chars of the answer. A case
     whose slash prompt was not sent records `ok=False` with `inconclusive` in the detail.
AC3. `probe_loopback` (docstring starts `V27:`): starts an `HTTPServer` on `127.0.0.1`, port 0, in a
     thread, that records each request path; a random token per run in the path. The shell grant's
     sandbox record as `probe_sandbox` uses (`enabled: true`, `allowUnsandboxedCommands: false`,
     none of `excludedCommands`, `allowUnixSockets`, `allowLocalBinding`). Bash is told to run
     `curl -sS -m 5 http://127.0.0.1:<port>/<token>-ip` and `curl -sS -m 5 http://localhost:<port>/<token>-name`
     and report each exit status. Cases, each target its own `record` line:
     - control: no `sandbox` settings: expect both reached (proves the server and the model work);
     - sandbox, `allowedDomains: []`: expect neither reached;
     - sandbox, `allowedDomains: ["example.com"]` (a plain-domain allowlist, TECHNICAL 4.2): expect
       neither reached.
     "Reached" is decided only by the server's own log (the token path arrived), never by the
     model's text. Detail: `reached=`, and whether a Bash tool_use naming the port was sent
     (`curl sent=`); a sandbox case with `curl sent=False` is `ok=False`, `inconclusive`. The server
     is shut down at the end, also on an exception.
AC4. The module docstring lists the two new names in its usage lines; no existing probe changes.
AC5. `python3 -I -c "import ast,sys; ast.parse(open('proto/claude-probes/probes.py').read())"` and
     `python3 -I proto/claude-probes/probes.py nosuch` (prints `nosuch` crash line, exits) work
     without `claude` logged in beyond the version line; the gate passes.
