## Goal

A Claude session runs on a provider stream the kernel tracks: the call that
starts its first turn (or a turn after the stream was released) opens one,
records it in `stream/<id>` (`{session, kind: "provider"}`) and the record's
`streams`, and takes a provider slot (8 kernel-wide, 4 per owner, 9.5
"Slots"); a `start` or `say` that would need a ninth, or an owner's fifth, is
refused `busy` and waits for nothing, and a retry with the same key succeeds
once a slot is free. A provider's items arrive by stream id and find their
session through `stream/<id>`. The stream's `ended` frees its slot and keys.
After a restart the stale stream counts as released (R4), so the next `say`
of an idle session resumes the Claude session (`resume: true`), as 9.4 "Code
to change (a later slice)" owes; with `persist: false` there is nothing to
resume and that `say` starts a fresh one (`resume: false`).

## Acceptance

AC1. **Open.** `start` of a Claude profile calls `Host::open_stream()` once;
the returned id `t` gets `stream/t` = `{"session": <id>, "kind":
"provider"}` (charged to the owner, 9.3 Bytes), joins `rec.streams`, and the
call increments `slots.provider` and the owner's provider count (AC4). The
`Request::Turn` has `resume: false`. A `say` that starts a turn on a session
whose provider stream is live opens nothing, takes no slot, and sends
`resume: false`. A `say` that queues opens nothing.

AC2. **Busy.** With 8 provider slots held (any owners), or 4 held by the
caller, a `start`, or a `say` that would open a stream, is refused
`KernelError::Busy` whose text names the cap (`8 provider streams` or `4
provider streams per owner`), before any write (state snapshot equal) and
with no request sent; the key is not kept, so after a slot is freed (AC5) the
same call with the same key succeeds (case 52). A `say` that queues, or one on
a live stream, is never refused for slots.

AC3. **Items by stream.** New `Kernel::provider_item(&mut self, stream: &str,
event: ProviderEvent) -> Result<Called<()>, KernelError>` reads `stream/<id>`
as its first key, then acts as `provider` does on that session. An id with no
`stream/` key (never opened, ended, or of an older boot) changes nothing,
sends nothing and returns `Ok` with no pushes. `provider(session, event)`
stays, for tests: it finds the session's live provider stream (via
`rec.streams` and their `stream/` keys) and calls `provider_item`; with none,
it acts on the session directly as today.

AC4. **Counts.** The owner's provider count lives in `quota/<owner>`
(`Usage`, new fields, serde default, absent = 0) tagged with the boot number
of `slots` (9.1: counts of an older boot read as zero). `slots.provider` is
zeroed by R1 as today. After any sequence of opens, ends, deletes and
cancels, `slots.provider` equals the number of live `provider` stream keys of
this boot, and each owner's count those of its sessions.

AC5. **Ended.** `provider_item(t, ProviderEvent::Ended)` does what `Ended`
does today (closes asks) and also deletes `stream/t`, drops `t` from
`rec.streams`, and frees one kernel and one owner provider slot. `cancel`
sends `Request::Cancel` as today and does the same release at once (the
stream's later `ended` then finds no key: AC3). `delete` releases the same
way (its keys are already deleted uncharged; the slot counts drop).

AC6. **Resume.** A `say` (or `interrupt` replacement, or a queued input
started by a turn's end) that opens a provider stream for a session that has
had one before sends `Request::Turn { resume: true }`, unless the turn is
`resume-lost` or the profile's `persist` is `false`, then `resume: false`.
So: after `Ended`, after `cancel`, and after a restart (an `idle {completed}`
session of an older boot, R4 `idle` row: its stale stream is dropped, so the
next `say` opens a new one with `resume: true`, case 52's resume part). R5's
`unknown` case keeps sending `resume: true`. A turn on a live stream sends
`resume: false` as today.

AC7. **Restart.** R4 (the step and R6) drops stale ids from `streams` and
deletes their `stream/` keys as today; no slot count is decremented for them
(R1 zeroed the kernel count; the owner's count reads zero by its boot tag).

AC8. **Bounds.** A provider item that changes nothing about streams reads
exactly one key more than today (`stream/<id>`) and writes no slot or owner
key. `start` and an opening `say` each write `slots` and `quota/<owner>` at
most once.

## Interface

Provides to S26-3 and S26-4 (fixed):
- `Host::open_stream(&mut self) -> String`; `FakeHost` returns `t1`, `t2`, ...
  (its own counter, `next_stream`) and logs `HostCall::Open { stream }`.
- `Host::cancel_stream(&mut self, stream: &str)` (the consumer's `cancel`);
  `FakeHost` logs `HostCall::CancelStream { stream }`. This task calls it
  nowhere except where AC5 needs none (the host's `Request::Cancel` ends the
  provider stream); S26-3 calls it for the idle release.
- `Kernel::provider_item(stream, event)` as AC3.
- A private helper on `Kernel` that releases a session's provider stream
  (`stream/` key, `streams`, both counts), used by S26-3.
- `Usage` gains `provider: u32` and `slots-boot: u64` (kebab serde names),
  default 0.
- `Limits` gains `provider: u32` (default 8) and `owner_provider: u32`
  (default 4), as `owner_sessions` is a setting; the busy texts name the
  value set.
