## Goal
The OpenAI loop can read what the host's `https-stream` gives it, as pure, tested code: the first
item (`{status, headers}`), each server-sent event, an error body, and the way the stream ended are
classified into what the loop does next: go on, record a finished response with its output items
and usage, pause until a usage limit resets, retry with backoff, or fail with a named cause.

## Acceptance
AC1 `head`: `{"status":200,"headers":{...}}` reads as `Head {status: 200, sse: true}` when `content-type` is `text/event-stream` (parameters and case ignored); anything that is not that JSON is `None`.
AC2 `sse`: `response.output_item.done` gives `Sse::Item(item)`; `response.completed` gives `Sse::Completed {usage}` with `input_tokens`, `output_tokens` (0 when absent) and the `response.output` array when present (else empty); `response.failed` and an `error` event give `Sse::Failed(failure)`; any other parseable event `Sse::Event(v)`; bytes that are not a JSON object `Sse::Unreadable`.
AC3 (case 4) A 429 body with `usage_limit_reached` (in `error.type` or `error.code`) gives `Failure::UsageLimit {until}`: `until` from `resets_at` (Unix seconds) or else `now + resets_in_seconds * 1000`, or `None` when neither is there; a `response.failed` whose `error.code` is `usage_limit_reached` gives the same; both forms of the dev fake (dev TECHNICAL 18.3 `UsageLimit` and `Failed{code}`) are tested as literals.
AC4 Retryable (9.5) are exactly: status 5xx, 429 without `usage_limit_reached`, a stream ended `idle-timeout`, and one ended `failed: ...` (a connection error). `gone` is not retryable (the host ended it for a withdrawal or a lost grant). Every other non-2xx status is `Failure::Fatal` with a message naming the status and the body's `error.message` when there is one.
AC5 (case 3) `ended(cause, completed)`: a stream that ended `closed` (cause `None`) without `response.completed` is `Some(Fatal("the response ended before it completed"))`; after completed it is `None`; `no-account`, `no-app`, `consent-refused(..)`, `gone`, `cancelled` are `Fatal` naming the cause (`no-account`: "not signed in to ChatGPT"; `no-app`: "no app to sign in to ChatGPT"); `idle-timeout` and `failed: ...` are `Retryable`.
AC6 `backoff_ms(attempt)`: 1 000, 2 000, 4 000, 8 000, 16 000, 32 000 for attempts 1..=6 (never over 60 000), `None` from attempt 7 (retries ran out: the loop pauses with no time).

## Interface
`kernel/src/openai/answer.rs` (S40-1 creates `kernel/src/openai/mod.rs` with `pub mod answer;`; if it does not exist yet when you start, create `mod.rs` with `pub mod answer; pub mod wire;` and an empty `wire.rs` with a `//!` line, and `pub mod openai;` in `kernel/src/lib.rs`; leave them as they are if they exist), exactly:
```rust
#[derive(Debug, Clone, PartialEq, Eq)] pub struct Head { pub status: u16, pub sse: bool }
#[derive(Debug, Clone, Copy, Default, PartialEq, Eq)] pub struct Usage { pub input_tokens: u64, pub output_tokens: u64 }
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Failure { UsageLimit { until: Option<u64> }, Retryable(String), Fatal(String) }
#[derive(Debug, Clone, PartialEq)]
pub enum Sse { Event(Value), Item(Value), Completed { usage: Usage, output: Vec<Value> }, Failed(Failure), Unreadable(String) }
pub fn head(item: &[u8]) -> Option<Head>;
pub fn sse(item: &[u8], now: u64) -> Sse;
/// A response whose status is not 2xx: its whole body (the 64 KiB chunks joined).
pub fn error_body(status: u16, body: &[u8], now: u64) -> Failure;
/// How the stream ended (`cause` as `map::ended_cause` gives it; `None` is `closed`).
pub fn ended(cause: Option<&str>, completed: bool) -> Option<Failure>;
pub fn backoff_ms(attempt: u32) -> Option<u64>;
pub const MAX_ATTEMPTS: u32 = 6;
```
