## Goal
Sessions and named profile calls recognize only pinned profile versions; a prior string-list access value confers no power, and callers register themselves as clients through check or profiles.
## Acceptance
1. AC1: malformed, name-list, stale, mismatched digest or revision access refuses start/check/new work and is absent from profiles; a matching entry permits it.
2. AC2: stored profile changes block old sessions from new input and launch even after a new version is allowed; restoring bytes raises rev and requires a new answer.
3. AC3: profiles and check register qualifying callers once up to 64, with no registration by page or agent.
4. AC4: native tests for the new access rules cover valid and invalid pinned entries.
## Spec
VISION boundaries; FUNCTIONAL 3.1, 3.7; TECHNICAL 9.1, 9.3, 9.7, 9.10 Pinned entries, Clients, 14, 15, cases 78 and 80.
## Interface
Provides AccessEntry { profile: String, digest: String, rev: u32 } and ProfileIndexEntry { name: String, digest: String, rev: u32, bytes: u32, offer: Option<OfferLink>, stale: bool }; a pub(crate) access-standing helper to manage. Takes state.get/put and existing Host unchanged.
