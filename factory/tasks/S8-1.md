## Goal

A new module `kernel/src/adapters/` in the `agent-kernel` crate: the shared output type, the
Claude adapter, and a golden-fixture test runner. Feed it one Claude stream item (a stdout line
the host passed unchanged, or a host item `ask`, `check`, `ask-resolved`, `initialized`) and it
returns the ACP v1 updates, `_meta.watane` items and transcript entry drafts of TECHNICAL 9.8,
never an error. It is pure: no state I/O, no clock, no host; its only state is an in-memory
struct the caller owns. Entry storage, `i`, `at`, paging (9.4) and counters (9.7) are later
slices. The Responses adapter is S8-2, which reuses this task's types and runner.

## Acceptance

AC1. Libraries (13): `claude-codes` with `default-features = false, features = ["types"]` and
     `agent-client-protocol-schema` (v1 line, no `unstable_*` feature) are dependencies;
     `Cargo.lock` updated. The adapter parses each line with `claude-codes`
     (`ClaudeOutput` or the crate's equivalent) and builds updates from
     `agent_client_protocol_schema::SessionUpdate` (serialized with `serde_json`), so every
     `update` value is one that type deserializes. If a library fails to build, use serde types
     of the same shape and say so in the last message (the slice reports it).
AC2. Golden fixtures: one JSON file per Claude row of 9.8 under
     `kernel/tests/fixtures/adapters/claude/` (8 rows: `assistant` text and `stream_event`
     deltas; `thinking`; `TodoWrite`; `tool_use`; `tool_result`; `ask`/`check`/`ask-resolved`;
     `compact_boundary`; `result`), plus `unknown.json` for the row "anything else". Lines are
     realistic Claude 2.1.3xx stream-json (shapes as `claude-codes` 2.1.330 types them, with
     `uuid`, `session_id`, `message.id`). A test in `kernel/tests/it/adapters.rs` runs every
     fixture in `claude/` (and in `responses/` when that folder exists) and compares the output
     to `expected` as `serde_json::Value`; a failure names the file and the input index. Another
     test fails if a row text of 9.8 (the "From" column, copied as the `row` field) has no
     fixture.
AC3. `assistant` text block -> one `Out` with `update` `agent_message_chunk` holding the whole
     text and `entry` `message` (`uuid` = the line's `uuid`). `stream_event` `content_block_delta`
     `text_delta` -> `agent_message_chunk` with the delta, no entry. A fixture streams deltas and
     then the `assistant` line: the deltas give chunks without entries, the line gives the whole
     text with the entry (the update that finishes an entry carries all of it, so a client
     replaces the deltas it showed, as replay does; 9.4).
AC4. `thinking` block -> `agent_thought_chunk` with the whole thinking text; `thinking_delta`
     -> `agent_thought_chunk` with the delta. No entry (9.8 names none). `redacted_thinking` and
     a thinking `signature` produce nothing.
AC5. `tool_use` (any tool but `TodoWrite`) -> `tool_call` with `toolCallId` = the block's `id`,
     `title` = the tool name, `status` `pending`, `rawInput` = the input. `TodoWrite` -> `plan`
     with one entry per todo (`content`, `status` mapped `pending|in_progress|completed`,
     `priority` `medium`), and no `tool_call`.
AC6. `user` line with a `tool_result` block -> `tool_call_update` with `status` `completed`, or
     `failed` when `is_error` is true, and the output as text content; and an entry `tool` whose
     body is the finished ACP tool call: `toolCallId`, `title` (the tool name), `rawInput` (the
     input of its `tool_use`, kept in the adapter's memory), `status`, `content`. Output text
     over 65 536 bytes is cut at a UTF-8 boundary at or under that and the body gets
     `"_meta": {"watane": {"cut": <original byte length>}}` (9.4). A `tool_result` for
     `TodoWrite` gives the same `tool_call_update` and `tool` entry. A `tool_result` whose
     `tool_use_id` the adapter never saw still gives both, with `title` and `rawInput` null.
AC7. Host items (4.5): `{"type":"ask","id","tool","input","tool_use_id"?}` and
     `{"type":"check",...}` -> a `watane` item and an `ask` entry; `{"type":"ask-resolved","id","by"}`
     -> a `watane` item and an `ask` entry. Shapes are fixed in Interface. The tool call id is
     the item's `tool_use_id` (Claude's `can_use_tool` field, passed on by the host) and is
     never guessed from earlier `tool_use` blocks; absent, it is `null`. `tool` and `input` are
     copied unchanged into both the item and the entry. An `ask` has
     `expires-at` = `at` + 600 000 (the host's 10 minutes, 9.6); a `check` has none.
     `initialized` produces nothing.
AC8. `system` `compact_boundary` -> entry `compaction` with body
     `{"trigger": <compact_metadata.trigger>, "pre-tokens": <compact_metadata.pre_tokens>}`; no
     update.
AC9. `result` -> `usage` = the line's `usage` object unchanged, plus `idle: true` only when
     `claude` has reported itself idle: `idle` is true on the `Out` of whichever comes second in
     a turn, the `result` or a `system` `session_state_changed` with `state` `idle`. A
     `session_state_changed` with another state starts a new turn (both flags cleared). A fixture
     shows `result` then idle (idle on the idle line), idle without a `result` (no idle), and two
     `result`s with background work between them (idle only once, after the last).
AC10. Unknown (9.8, case 5 of 16): a line that is not JSON, JSON that `claude-codes` cannot
     parse, and a well-formed line of a type the adapter has no row for (a made-up
     `{"type":"brand_new"}`) each give one `Out` with entry `unknown` and body
     `{"raw": <the JSON value, or the line as a string when it is not JSON>}`, and the next line
     is adapted normally. Known lines with no row give nothing: `system` `init`, `status` and
     `session_state_changed`, `rate_limit_event`, `stream_event` other than text and thinking
     deltas. The adapter never panics: a test feeds 1 000 random byte strings and JSON values
     with wrong field types and checks each returns `Out`s.
AC11. One `assistant` line with several blocks gives one `Out` per block, in block order.
AC12. Pure: `kernel/src/adapters/` uses no `std::fs`, `std::time`, `std::env`, network or
     global state (a test greps the module's source for these).
     `cargo test` and `cargo clippy --all-targets -- -D warnings` pass in `kernel/`.

## Interface

Provides (S8-2 uses these exactly; names fixed):

```rust
// kernel/src/adapters/mod.rs
pub mod claude;
pub mod responses;               // S8-2 adds the file; this task may leave the line out

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize, Default)]
#[serde(rename_all = "kebab-case")]
pub struct Out {
    #[serde(skip_serializing_if = "Option::is_none")] pub update: Option<Value>,  // an ACP v1 SessionUpdate
    #[serde(skip_serializing_if = "Option::is_none")] pub watane: Option<Value>,  // goes under _meta.watane
    #[serde(skip_serializing_if = "Option::is_none")] pub entry: Option<Entry>,
    #[serde(skip_serializing_if = "Option::is_none")] pub usage: Option<Value>,   // for the counters (9.7)
    #[serde(skip_serializing_if = "is_false")]        pub idle: bool,             // idle {completed}
}
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct Entry {               // an entry of 9.4 without v, i, at: storage adds those
    pub kind: Kind,
    #[serde(skip_serializing_if = "Option::is_none")] pub uuid: Option<String>,
    pub body: Value,
}
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum Kind { Message, Tool, Ask, Compaction, Unknown }

pub fn unknown(raw: Value) -> Out;   // the `unknown` entry, body {"raw": raw}
pub fn cut_output(text: &str) -> (String, Option<usize>);  // AC6's 64 KiB cut

// kernel/src/adapters/claude.rs
#[derive(Debug, Default)]
pub struct ClaudeAdapter { /* tool_use id -> (name, input); turn flags */ }
impl ClaudeAdapter {
    pub fn new() -> Self;
    pub fn line(&mut self, line: &[u8], at: u64) -> Vec<Out>;   // at: ms since epoch, from the caller
}
```

Updates are `SessionUpdate` JSON, e.g. `{"sessionUpdate":"agent_message_chunk","content":{"type":"text","text":"…"}}`.
`message` entry body: `{"role": "agent", "content": [<ACP content blocks>]}`.

`watane` items (fixed):
- ask/check: `{"type":"ask","id":<host id>,"kind":"ask"|"check","toolCall":{"toolCallId":<tool_use_id|null>,"title":<tool>,"rawInput":<input>},"options":[…],"expires-at":<ms>}`
  (`expires-at` absent for a check). Options, as ACP `PermissionOption`: an ask
  `[{"optionId":"allow","name":"Allow","kind":"allow_once"},{"optionId":"allow-session","name":"Allow for this session","kind":"allow_always"},{"optionId":"deny","name":"Deny","kind":"reject_once"}]`;
  a check `[{"optionId":"none","name":"No objection","kind":"allow_once"},{"optionId":"deny","name":"Deny","kind":"reject_once"}]` (a check never allows, 4.5).
- `{"type":"ask-resolved","id":<host id>,"by":<by>}`.

`ask` entry bodies: the ask `{"id","kind","tool-call-id","tool","input","expires-at"?}`; its
resolution `{"id","by"}`.

Fixture file (both adapters):
```json
{"row": "<9.8 From column, verbatim>",
 "input": [{"at": 1763600000000, "line": <JSON>} | {"at": …, "raw": "<not JSON>"}],
 "expected": [[<Out>, …], …]}          // one list per input, in order
```
S8-2 adds `{"at", "event": <JSON>}` and `{"job": {"call", "output", "ok"}}` inputs for
`responses/`; the runner here must dispatch on the folder, so S8-2 only adds a branch.
