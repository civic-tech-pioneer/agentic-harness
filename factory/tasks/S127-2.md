## Goal
A new mod `provider-checked/` (`mods:claude-code@0.1.0`, R-B1), the checked Claude Code provider: only the kernel
may start it; it starts `claude` with `pre-tool-check`, forwards every item to its own stream to the kernel,
and judges the launch input, every later input, every `check` and every `ask` with TypeSafe System One at its
build origin before the input reaches `claude` or the check is answered. A safe call goes on; an unsafe, unsure,
unreadable, slow (deadline), refused or failed one denies. Each judge call is announced by a `checking` item and
ends with a `verdict` item. 3 denials in a row or 10 of the last 50 interrupt the session (the breaker).
Decision at the boundary (why `high`): an ask is answered only `deny`; "safe" never answers `allow`; anything
the provider cannot read as a verdict is a denial.
## Acceptance
AC1. Every `sessions` function, called by anyone but the kernel identity (`AGENT_KERNEL_IDENTITY`, default
     `local/agent`, exact bytes), returns `not-owner` and makes no host call (case 32: no judge request).
AC2. `start` calls `claude-code.start` with the launch unchanged but `pre-tool-check` set, opens its own stream,
     stores the pending inputs and returns `{stream: <own>, direct: false}` in the same call; it makes no judge
     call and no `say` (case 37). `start` with a launch that is not a JSON object is `bad-launch`.
AC3. Inputs (launch input, each `say`) wait for the first `initialized` item; then are judged one at a time in
     order; each reaches `claude-session.say` only after its safe verdict; no input before the launch's safe
     verdict. A second `initialized` changes nothing (cases 43, 47, 50).
AC4. Unsafe/unsure on the launch: a verdict item, then cancel the `claude` stream and close the own stream.
     Unsafe/unsure on a later input: a verdict item only; that input is dropped; the stream stays (case 38).
AC5. A `check` gets `claude-session.answer(..., none)` only after a safe verdict, `deny(<reasons>)` otherwise.
     An `ask` gets `deny` after a not-safe verdict and no answer after a safe one; the kernel's `answer` for an
     ask whose verdict is pending is kept and forwarded only after a safe verdict, dropped after a deny
     (case 42). The kernel's `answer` for an id the provider does not hold as an ask is forwarded unchanged
     (the host decides: `unknown-ask`); the provider alone answers checks.
AC6. Each judge call: before it a `{"type":"checking","on":<on>}` item; `https-stream.start` with the request of
     Interface, `account: "judge"`; a timer `judge/<own stream>/<on>` at `timeout-s - 2 s` (launch's
     `pre-tool-check.timeout-s`, default 60 when absent). The first readable verdict or the timer is final; a
     late one changes nothing (case 38). A new attempt only after an error or an ending with no readable
     verdict, while the deadline is ahead, at most 3 (case 44: an unsafe body is counted as one request).
     A refused `timers.after` or `https-stream.start` is unsafe at once (case 50).
AC7. Two sessions with the same `on` keep separate timers and verdicts (case 46).
AC8. `interrupt` drops every input waiting for a verdict or for `initialized` and calls
     `claude-session.interrupt`; a later verdict for one sends nothing (case 47).
AC9. Breaker: after 3 denials in a row or 10 of the last 50 verdicts, `claude-session.interrupt` and a verdict
     item `on: "breaker"` whose reason names the rule; every verdict item carries `denials-in-a-row`; a safe
     verdict resets the run of denials.
AC10. When the own stream is full, the item call returns `defer` and resumes on `ready` in a later call (10.7).
AC11. Settings: `settings.get` returns `{"unsafe-at":0.7,"safe-at":0.3,"origin":"<build origin>"}`;
     `settings.set` (only the caller `page`; others `not-owner`) stores thresholds with
     0 <= safe-at < unsafe-at <= 1, else refused. A page in `ui/` shows and sets them and shows the origin.
AC12. `cargo test`, `cargo fmt --check`, `cargo clippy -- -D warnings` in `provider-checked/logic` pass, with
     the scripted judge played as `Raw` System One bodies in the tests (no network); `factory/gate.sh` runs
     them (one block, as for `provider/`).

## Interface
Fixed. Items the provider pushes on its own stream, besides the forwarded host items (unchanged bytes):
- `{"type":"checking","on":"<on>"}`
- `{"type":"verdict","on":"<on>","outcome":"safe"|"unsafe"|"unsure","reasons":["<text>",...],"denials-in-a-row":<n>}`
- breaker: `{"type":"verdict","on":"breaker","outcome":"unsafe","reasons":["<rule>: the session was stopped"],"denials-in-a-row":<n>}`
`<on>`: the host's ask or check `id`, `launch`, or `input/<n>` (n from 1, the launch input first).
Judge request (System One), `POST <origin>/v1/systemone`, body:
`{"model":"jev-latest","state":{"kind":"tool"|"input","tool":"<name>"?,"input":<object>?,"text":"<input text>"?},
  "questions":{"unsafe":{"type":"noul","instructions":"<harm question, yes = harm>"},
               "off_task":{"type":"noul","instructions":"<off-task question, yes = harm>"}}}`
headers `content-type: application/json` only (the host adds the key). Judge answer read: the body of a
200 status, JSON, `answers.<question>.noul` (D1.1) a number in [0,1] for every question asked; anything else
(other status, missing question, not a number, out of range) is unreadable. Mapping (thresholds from settings):
unsafe when any question >= unsafe-at; safe when every question <= safe-at; else unsure. Reasons: one per
question `"<question>: <p with 2 decimals>"`. All of this lives in `src/judge.rs` (build, read, map).
Origin: compile-time `JUDGE_ORIGIN`, default `https://api.typesafe.ai`; `mod.toml` `[http] hosts =
["api.typesafe.ai"]`.
World `claude-code-checked`: imports caller, state, streams, claude-types, claude-code, claude-session,
https-stream, timers; exports `sessions` (as `provider/wit/world.wit`), `settings`, stream-sink,
stream-producer, timer-sink.
