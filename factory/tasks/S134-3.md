## Goal

A child cannot be wider than its root (sketch outcome 2, the boundary "A child cannot widen its
owner's authority", TECHNICAL 14). This task builds the pure admission check of TECHNICAL 9.7
"Admission" steps 2 to 5 in `kernel/src/delegation.rs`, which S134-4 calls at dispatch, and the
profile rules of 9.2 and 11 for the stage F fields: `delegates` and `subagent-limits` are accepted
only on OpenAI and `subagent-limits` is validated by key; a Claude profile (or a compiled Claude
profile with an overlay) with `max-tokens` or `max-tool-errors` is refused (S132's Door C choice).

## Acceptance

AC1. `check` of a Claude profile with `delegates: ["x"]`, `subagent-limits: {}`, `max-tokens: 5` or
     `max-tool-errors: 3` -> one refusal each, on that field, backend `claude`. A Claude profile
     with an overlay `{"max-tokens": 5}` is refused on `max-tokens` too.
AC2. OpenAI `subagent-limits`: `{"live": 2}` and `{"live": 20, "depth": 1}` pass; `{"live": 0}`,
     `{"live": 21}`, `{"depth": 2}`, `{"depth": 0}`, `{"live": "2"}`, `{"wide": 1}` are refused on
     `subagent-limits.live`, `subagent-limits.depth` and `subagent-limits.wide`.
AC3. `admit` step 2: a caller that is a child -> exactly one refusal `subagent-limits.depth`, and
     the loader is not called.
AC4. Step 3: a name not in the root's effective `delegates`, or a name in it whose loader returns
     `None` (missing or unadopted) -> one refusal `profile`; for the unnamed case the loader is not
     called.
AC5. Step 4: `live` equal to the root's effective cap (default 4) -> one refusal
     `subagent-limits.live`, loader not called.
AC6. Step 5, one test per row of the child-rule table of 9.7, each giving that field and only it:
     a Claude or other-model candidate (`backend`, `model`); an extra toolset (`toolsets`); a
     candidate with `tools`, `workspace` or `extra-workspaces` (refused by 11 as today); a different
     `mode`, `ask` or `pre-tool-check`; an allow rule the root lacks, a glob `x*` where the root has
     `x1` (compared as written: refused), and a missing root deny (`allow`, `deny`); a higher or
     absent `max-turns`, `max-tool-errors`, `max-tokens` or `ask-expiry` under a root that sets it,
     and any value under a root that sets none (passes); `delegates` or `subagent-limits` on the
     candidate; `persist: true` (or absent) under a `persist: false` root (`persist`). Several
     failures in one candidate are all returned at once. Each refusal has backend `openai` and the
     root's model.
AC7. A candidate equal to the root, and one strictly narrower on every field, are admitted and
     `admit` returns the candidate's compiled profile.
AC8. The root's effective profile is the compiled one: an overlay that removed an allow or lowered
     `max-turns` on the root makes a candidate with the original value refused.

## Interface

Provides, in `kernel/src/delegation.rs` (fixed; S134-4 calls it):
```rust
/// The root's effective `subagent-limits` (9.2 defaults: live 4, depth 1).
pub fn live_cap(root: &Profile) -> u32;
/// Steps 2 to 5 of 9.7 Admission. `root`: the root's compiled profile (profile, offers, overlay);
/// `root_model`: its model; `caller_is_child`: the calling session has a parent; `live`: the
/// root's live children now; `load`: the named profile's JSON (`None`: missing or unadopted),
/// called only after steps 2 to 4 pass. Ok: the candidate's compiled profile (no overlay).
pub fn admit(
    root: &Profile,
    root_model: &str,
    caller_is_child: bool,
    live: u32,
    name: &str,
    load: impl FnOnce(&str) -> Option<String>,
) -> Result<Profile, Vec<Refusal>>;
```
`Profile` is `crate::profile::Profile`; `Refusal` is `crate::error::Refusal`. Step 1 (the root's
access) is the caller's (S134-4). Register the module in `kernel/src/lib.rs`.
