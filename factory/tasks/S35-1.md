## Goal

The kernel crate runs a real Claude session's turn. A Claude `start` builds the launch document of
TECHNICAL 4.1 from the profile (and overlay) and the session's workspace, and hands it with the
input to the provider; the provider answers `{stream, direct}`. Each item of the provider stream
arrives as the raw line it is (a `claude` stdout line or a host item) and goes through the Claude
adapter (9.8, S32 R2), whose state is kept in `adapter/<stream>` between calls (9.8 "Adapter
state"); the `initialized` item's workspace and `system/init`'s `session_id` are kept in the
record. Later turns go to the provider stream as text (`Request` names the stream and whether it is
direct), or, with no live stream, start a new one that resumes the Claude session in the same
scratch workspace. A provider stream that ends with anything but `closed` ends an active turn
failed with its cause. The page gets the built-in profile `scratch` on first run (9.1). A
`Buffered` state lets the WASM wrapper commit a call's writes only on success (S32 R1). The stage
A probe (9.9) is removed.

## Acceptance

AC1. Launch (4.1): with a stored Claude profile `{"backend":"claude","model":"sonnet","tools":["Read"],
     "allow":["Read(**)"],"partial":true,"max-tokens":5}` and access, `start(owner, k, "p", "{}", input)`
     records `HostCall::StartProvider { launch, input }` whose `launch` parses to exactly
     `{"version":1,"profile":"p","workspace":"scratch","model":"sonnet","tools":["Read"],"allow":["Read(**)"],"partial":true}`
     (no kernel-only field: `backend`, `toolsets`, `delegates`, `max-tool-errors`, `max-tokens`,
     `ask-expiry`, `subagent-limits`; no `session` on a first launch). An overlay's narrowing shows in
     the launch (`tools-: ["Read"]` gives `"tools":[]`, `max-turns` lowered gives the lower value). A
     profile name outside `[A-Za-z0-9._-]{1,64}` gives no `profile` field.
AC2. `start` sends no `Request::Turn` (the provider's `start` carries the input, 10); the turn is
     `running` and the user `message` entry is stored as before.
AC3. `Host::start_provider` returns `Result<Started, String>` (`Started { stream, direct }`); a
     `direct: false` answer is kept in `stream/<id>` (`checked: true`, absent when false) and its items
     go through `ClaudeAdapter::checked()`; a direct one through `ClaudeAdapter::new()`. An `Err(cause)`
     refuses `start` `backend(cause)` and writes nothing (as today).
AC4. Raw items: `Kernel::provider_lines(stream, Vec<(u64, Vec<u8>)>) -> Result<Called<SinkOutcome>, KernelError>`
     feeds each body to the adapter in `seq` order (dropping `seq` at or below `last`, as
     `provider_batch`) and acts on each `Out` as `provider_batch` acts on `ProviderEvent::Out`. With the
     dev fake's default turn as lines (fixture `kernel/tests/fixtures/adapters/fake_default.jsonl`:
     `system/init` with a `session_id`, a `stream_event` text delta "This is the fake claude.", the
     finished `assistant` message, `result`, `{"type":"system","subtype":"session_state_changed","state":"idle"}`),
     delivered as one batch and again as one item per call: the owner stream gets the delta live as an
     `AgentMessageChunk` update, then the agent `message` entry once, then `turn` `idle {completed}`;
     the transcript holds exactly one agent message; `read` after it is the same as the live entries.
AC5. Adapter state: thinking deltas in one call and the finished `assistant` message holding the same
     `thinking` block in a later call give one `thought` (9.4), not two; a `tool_use` in one call and
     its `tool_result` in a later call give one `tool` entry with the tool's name. `adapter/<stream>`
     is written at most once per items call, is deleted with `stream/<id>` (ended, cancel, delete),
     and a deferred call (live owner stream `full`) leaves it unchanged (a state snapshot before and
     after compares equal).
AC6. `{"type":"initialized","workspace":"scratch:0123456789abcdef0123456789abcdef"}` sets the record's
     `workspace` once and gives no entry; a later `initialized` with another id is an `unknown` entry
     and does not change it. `system/init`'s `session_id` sets `claude-uuid` (no entry).
AC7. Later turns: `say` on an idle session with a live provider stream sends
     `Request::Turn { session, stream, direct: true, input, .. }` (the `stream` the session holds), and
     `pub fn input_text(input: &str) -> String` gives the text the wrapper sends: the `text` of the ACP
     text blocks joined with "\n\n", other blocks left out (`[{"type":"text","text":"a"},{"type":"image",...},{"type":"text","text":"b"}]`
     gives `"a\n\nb"`). `say` on a session with no live provider stream (it ended, or the idle release
     dropped it) calls `start_provider` in that call, before its first write, with the launch of AC1
     plus `"workspace":"<record workspace>"` (when kept, else `scratch`) and `"session":{"resume":"<claude-uuid>"}`
     (when kept and the profile's `persist` is not false), registers the new stream, and sends no
     `Request::Turn`. `interrupt` and `answer` requests carry `stream` and `direct` the same way;
     the owner's `cancel` is `HostCall::CancelStream` of the provider stream (as today, if it is).
AC8. Ended with a cause: `Kernel::provider_ended_with(stream, cause: Option<String>)`
     (`provider_ended(stream)` stays and is `cause: None`): with `Some("no-binary")` while `running`,
     the turn becomes `idle {failed {error: "provider-ended", cause: "no-binary"}}` (`Stop::Failed`
     gains `cause: Option<String>`, skipped when `None`); `None` keeps today's behaviour exactly.
AC9. Built-in profile (9.1): with no `access/page` and no `profile/scratch`, `start("page", k,
     "scratch", "{}", input)` starts a Claude session whose launch is
     `{"version":1,"profile":"scratch","workspace":"scratch","partial":true}`; `"other"` for `page`, and
     `"scratch"` for any other identity (`local/notes`), are refused `{field: "profile"}` as today; an
     unreadable `access/page` (`"x"`) allows none; a stored `access/page` `["p"]` no longer allows
     `scratch`; a stored `profile/scratch` is used instead of the built-in.
AC10. R1: `state::Buffered<S: State>` wraps a state: `get` sees its own puts and deletes, nothing reaches
     the inner state until `commit(self) -> S`; `discard(self) -> S` drops them. A test runs a
     `Kernel<Buffered<MemState>, FakeHost>` call that writes and then fails (find one; if no call of
     the crate writes before an error today, say so in your report and test the type alone) and shows
     that after `discard` the inner state is unchanged.
AC11. The probe is gone: `probe_start`, the `probe` record field and deadline, `no_input()`, and the
     tests that only test the probe; every other test still passes. `cargo test`, `cargo clippy
     --all-targets -- -D warnings`, `cargo fmt --all --check` pass in `kernel/` (`kernel/wasm` may fail
     to compile against the changed crate: S35-2 fixes it; run `cargo test -p agent-kernel`).

## Interface

Provides to S35-2 (the WASM wrapper), fixed:
- `pub struct Started { pub stream: String, pub direct: bool }`, exported at the crate root;
  `Host::start_provider(&mut self, launch: &str, input: &str) -> Result<Started, String>`.
- `Request::Turn { session: String, stream: String, direct: bool, input: String, resume: bool }`,
  `Request::Interrupt { session, stream, direct }`, `Request::Answer { session, stream, direct, ask, decision }`,
  `Request::Cancel { session, stream }` (each field a `String` but `direct: bool`, `decision: Value`).
- `pub fn input_text(input: &str) -> String` at the crate root.
- `Kernel::provider_lines(&mut self, stream: &str, items: Vec<(u64, Vec<u8>)>) -> Result<Called<SinkOutcome>, KernelError>`.
- `Kernel::provider_ended_with(&mut self, stream: &str, cause: Option<String>) -> Result<Called<()>, KernelError>`.
- `pub struct Buffered<S: State>` in `state.rs`, exported at the root: `Buffered::new(inner: S)`,
  `impl State`, `commit(self) -> S`, `discard(self) -> S`.
- `Kernel::probe_start` no longer exists.
