## Goal

After this task `console/` is a TypeScript package with its test run, and holds the console's
data side with no screen yet: the wire messages a kernel stream carries (an assumed shape, kept
in one file), a pure reducer that turns them into a session view (the rows of TECHNICAL 18.3),
the attach / behind / read / reattach loop of 18.3 that drops every index already shown, and a
scripted fake kernel with the shape of `attach` and `read` (TECHNICAL 2.3, 9.4) that plays the
story's session: a user message, thinking, three reads and a search, an edit with its diff, an
open ask, turn and queue and usage items.

## Acceptance

AC1. `npm ci && npm test` in `console/` runs Vitest (jsdom available for later view tests) and
     passes; `npm run typecheck` (`tsc --noEmit`, strict) passes.
AC2. Reducer, one test per row of 18.3, from wire messages to `SessionView.rows` and fields:
     user `message` entry -> `user` row; `agent_thought_chunk` updates -> one `thought` row,
     `streaming: true` while chunks arrive, then `streaming: false` with `seconds` once the
     agent message (or any other update) follows; `tool_call`s of kind `read`/`search` in a row
     -> one `explored` row with `reads` and `searches` counts (a non-read/search row in between
     starts a new one); `tool_call` of kind `edit`/`execute`/other or any `failed` call -> one
     `tool` row whose `call` holds content (diff `oldText`/`newText`) and status, updated in place
     by `tool_call_update`; an open `ask` -> its `tool` row gets `ask` and `openAsks` lists it;
     a decided `ask`, an `allow`, a `verdict` -> a `decision` row with `who`, `what`, `reason`;
     `plan` -> `view.plan`; `turn` item -> `view.turn`, and a turn reaching `idle` adds a
     `footer` row (seconds, tool count, tokens when known); `queue` -> `view.queue`; `usage` ->
     `view.usage`; an `allow` given / taken back adds / removes `view.allows`; `unknown` entry
     kind, an entry with a newer `v`, or a wire message the parser does not know -> an `unknown`
     row holding the raw value. An `agent_message_chunk` stream -> one `agent` row, `writing:
     true` until the update with `_meta.watane.i` finishes it.
AC3. Replay: entries before `synced` replace nothing already shown, and an entry whose `i` is
     at or below `view.lastIndex` is dropped (a test feeds a replay that overlaps the shown
     rows: no row doubles). `synced {through}` sets `view.synced` and `lastIndex >= through`.
AC4. Mid-message attach (9.4 "no partial replay", case 30): `synced` carries `"writing":true`
     when a message was being written at attach (a wire assumption of this slice). Its later
     deltas are dropped; the view has a `writing` row with `text: ""` (shown as "Writing…") until
     the update with `_meta.watane.i = n` finishes it; then `openSession` reads entry n
     (`read(session, n-1, 1)`) and it shows once, whole. A message whose first chunk arrives
     after a `synced` without `writing` streams normally.
AC5. `openSession` with the fake: a first open attaches with `after: 0`; after the stream drops
     (`fake.drop()`), it reattaches with `after: view.lastIndex` (assert the argument) and the
     rows equal the rows before the drop plus the new ones, none doubled. A second, fresh
     `openSession` on the same fake (a page reload) ends with the same rows as the first.
AC6. `behind`: with the fake holding more than 128 entries after `after`, `attach` returns
     `{behind: through}`; `openSession` pages with `read` (at most 256 per call, newest page
     first), then attaches again with `after: through`; the rows are every entry once, in index
     order.
AC7. The fake's `story` script plays the slice's session and the view at its end has: one
     `user` row, a folded `thought` row, an `explored` row with 3 reads and 1 search, an edit
     `tool` row with a diff, an open ask on a second edit, `turn` waiting with `expiresAt`, a
     queue of one input, usage, and a plan of 3 with 1 done.

**The wire (an assumption of this slice, kept only in `console/kit/wire.ts`).** 9.4 does not fix
how a live entry without an ACP form travels, nor the body fields. Parse these, and nothing else
outside that file may know them (foreman decisions in round 1: an `ask` body also carries
`toolCall`, the ACP ToolCall as known when the ask opened; after `synced` attach pushes the
current `turn`, `queue`, `usage` and the last `plan`; `synced` may carry `writing: true`):
- An entry, as 9.4 states, from `read` and from attach replay before `synced`:
  `{"v":1,"i":n,"kind":k,"at":ms,"body":{...}}`. Bodies: `message`: `{"role":"user"|"agent",
  "content":[ACP content blocks], "thought"?:{"text":s,"seconds":n}}`; `tool`: an ACP v1 ToolCall
  (`toolCallId`, `title`, `kind`, `status`, `content`, `locations`, `rawInput`, `rawOutput`);
  `ask`: `{"toolCallId","input","expiresAt", "decision"?:{"outcome":"allow"|"deny",
  "for"?:"session","reason"?,"by"}}`; `allow`: `{"id","reach","given"|"takenBack":true,"by"}`;
  `verdict`: `{"toolCallId","outcome","reasons":[..],"by"}`; `turn`: a turn state of 9.3 (below);
  `compaction`: `{"tokensBefore"}`; `unknown`: `{"raw"}`.
- A live ACP v1 update: the `SessionUpdate` object (`{"sessionUpdate":"agent_message_chunk",
  "content":{...}}`, `agent_thought_chunk`, `user_message_chunk`, `tool_call`,
  `tool_call_update`, `plan`), with `"_meta":{"watane":{"i":n}}` on the update that finishes
  entry n.
- A watane item: `{"_meta":{"watane":{"type":T, ...}}}` with T one of `synced {through}`,
  `turn {state}`, `queue {inputs:[{n,input}]}`, `usage {"context-used","context-window",
  "compact-at"?}`, and `entry {entry}` for a live entry of a kind with no ACP update (`ask`,
  `allow`, `verdict`, `turn`, `compaction`, `unknown`).
- Turn state: `{"state":"running","activity"?:{"kind":"checking","on"?}|{"kind":"compacting"}|
  {"kind":"consent","what"},"since":ms}`, `{"state":"waiting","asks":[toolCallId],"expiresAt":ms}`,
  `{"state":"paused","until":ms}`, `{"state":"idle","stop":{"kind":"completed"|"interrupted"}|
  {"kind":"stopped","limit"}|{"kind":"failed","error"},"seconds"?,"tools"?,"tokens"?}`,
  `{"state":"unknown"}`, `{"state":"resume-lost"}`.

## Interface

Provides (fixed; S4-2 and S4-3 build on these exact names):

```ts
// console/kit/model.ts
export type ToolKind = "read"|"edit"|"delete"|"move"|"search"|"execute"|"think"|"fetch"|"other";
export type ToolStatus = "pending"|"in_progress"|"completed"|"failed";
export type ToolContent =
  | { type: "content"; content: { type: "text"; text: string } }
  | { type: "diff"; path: string; oldText: string | null; newText: string }
  | { type: "terminal"; terminalId: string };
export interface ToolCall { id: string; title: string; kind: ToolKind; status: ToolStatus;
  content: ToolContent[]; locations: { path: string; line?: number }[]; rawInput?: unknown; rawOutput?: unknown }
export interface Decision { outcome: "allow"|"deny"; for?: "session"; reason?: string; by: string }
export interface Ask { toolCallId: string; input: unknown; expiresAt: number; decision?: Decision }
export type Activity = { kind: "checking"; on?: string } | { kind: "compacting" } | { kind: "consent"; what: string };
export type TurnState =
  | { state: "running"; activity?: Activity; since: number }
  | { state: "waiting"; asks: string[]; expiresAt: number }
  | { state: "paused"; until: number }
  | { state: "idle"; stop: { kind: "completed" } | { kind: "interrupted" } | { kind: "stopped"; limit: string } | { kind: "failed"; error: string } }
  | { state: "unknown" } | { state: "resume-lost" };
export type Row =
  | { kind: "user"; key: string; i?: number; text: string }
  | { kind: "agent"; key: string; i?: number; text: string; writing: boolean }
  | { kind: "thought"; key: string; i?: number; text: string; streaming: boolean; seconds?: number }
  | { kind: "explored"; key: string; reads: number; searches: number; calls: ToolCall[] }
  | { kind: "tool"; key: string; i?: number; call: ToolCall; ask?: Ask }
  | { kind: "decision"; key: string; i?: number; who: string; what: string; reason?: string }
  | { kind: "footer"; key: string; seconds: number; tools: number; tokens?: number }
  | { kind: "unknown"; key: string; i?: number; raw: unknown };
export interface PlanItem { content: string; status: "pending"|"in_progress"|"completed" }
export interface SessionView {
  rows: Row[]; openAsks: string[]; turn: TurnState | null;
  queue: { n: number; input: string }[]; plan: PlanItem[] | null;
  usage: { used: number; window: number; compactAt?: number } | null;
  allows: { id: string; reach: string }[]; lastIndex: number; synced: boolean;
}
export const emptyView: SessionView;
export interface Actions {
  say(text: string): void;
  answer(toolCallId: string, decision: { outcome: "allow"|"deny"; for?: "session"; reason?: string }): void;
  stop(): void;
  takeBack(allowId: string): void;
}
// console/kit/reduce.ts
export function reduce(view: SessionView, message: string): SessionView;   // one stream message (JSON text)
// console/kit/kernel.ts: the subset of TECHNICAL 2.3 the console uses, as a page sees it
export interface Kernel {
  attach(session: string, after: number, onMessage: (json: string) => void, onEnd: (reason: string) => void):
    Promise<{ ok: true } | { behind: number }>;
  read(session: string, after: number, max: number): Promise<string[]>;
  say(session: string, key: string, input: string): Promise<number>;
  answer(session: string, key: string, ask: string, decision: string): Promise<void>;
  interrupt(session: string, replacement?: string): Promise<void>;
  takeBack(session: string, allow: string): Promise<void>;
}
export function openSession(kernel: Kernel, session: string, onView: (v: SessionView) => void): { close(): void };
// console/fake/kernel.ts
export interface FakeKernel extends Kernel { drop(): void; play(step?: number): void; calls: { name: string; args: unknown[] }[] }
export function fakeKernel(script: string[][], opts?: { preload?: string[] }): FakeKernel;
// script: steps, each a list of stream messages; preload: entries already stored
// console/fake/story.ts
export const story: string[][];   // the slice's session (AC7)
```

`key` of a row is stable across replay and live (from the entry index, `e<i>`, or the tool call
id), so React keys and dedup agree.
