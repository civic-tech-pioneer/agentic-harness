## Goal

A client attaches to a session and gets its live updates on an owner stream
the kernel tracks (9.4 `attach`, "A full owner stream", "A stream finds its
session without the record"): `attach` replays the entries after `after`,
registers the stream in `stream/<id>` (`kind: "owner"`) and `live/<session>`,
and ends an earlier live stream `replaced`. Every push of the session goes to
that stream. When the stream is full the kernel defers its provider stream in
an item call, or closes the owner stream `lagging` outside one; `ready`
resumes the provider stream; the owner stream's `ended` resumes it too, and
the kernel then stores entries without pushing them. A provider item that
only forwards a delta reads `stream/<id>` and `live/<session>` and nothing
else (P09). Tested with a fake owner stream (`FakeHost`).

## Acceptance

AC1. **Attach.** New `Kernel::attach(&mut self, caller: &str, session: &str,
after: u64) -> Result<Called<Attached>, KernelError>`, `pub enum Attached {
Live { stream: String }, Behind { through: u64 } }`. Owner check and R6 as
other calls (`not-owner`, `unknown-session`). With more than 128 entries or
2 MiB after `after` (the transcript's `replay`): `Behind {through}`, opens
nothing, writes nothing. Else it calls `Host::open_stream()` (id `o`),
writes `stream/o` = `{"session", "kind": "owner"}` and `live/<session>` =
`o` (both charged; written past quota too, 9.3 Quota), adds `o` to
`rec.streams`, and pushes on `o`, in order: each replayed entry as `{"_meta":
{"watane": {"type": "entry", "entry": <entry>}}}`, then `{"type": "synced",
"through": <last>}`, the current `turn` item and the `queue` item (9.4 "The
wire"). `Attached::Live {stream: o}`.

AC2. **Replaced.** An `attach` while `live/<session>` names `p`: `p` is
closed with `Host::close_stream(p, "replaced")`, its `stream/p` deleted and
`p` dropped from `rec.streams` in that same call (9.3 Sizes, `streams` row);
a later `stream_ended(p)` finds no key and changes nothing (the new stream
stays live).

AC3. **Live pushes.** Every `Push` a call collects for a session with a live
owner stream is also pushed to it (`Host::push(stream, value) ->
Result<(), Full>`, `pub struct Full;`), in order, after the call's last
write; `Called.pushes` keeps returning them as today. A provider `Out` with
an `update` is pushed as the update with `_meta.watane.at` (and
`_meta.watane.i` when it finishes an entry, 9.4 "The wire").

AC4. **Delta forwarding (P09).** A `provider_item` whose `Out` has only an
`update` (no entry, resolved, idle, usage) reads exactly `stream/<id>` and
`live/<session>` (assert `get_keys()`), writes nothing (counts), and pushes
the update to the live stream, or to nothing when none is live.

AC5. **Full in an item call.** When `Host::push` fails `Full` during a
`provider_item`: the call returns `Ok` with `Called { value: Item::Defer }`
(the item call's result becomes `pub enum Item { Done, Defer }`; S26-2's
`provider_item` returns `Called<Item>`, `Done` otherwise) and is rolled back
whole: the state after equals the state before (snapshot of
`MemState::entries()`), no request is sent, no timer set (3 "Deferred
batch"; 7). The same item delivered again after `stream_ready` is applied
once. The kernel holds no record of the deferral (resume of a stream that is
not deferred does nothing, 3).

AC6. **Full outside an item call.** When a push fails `Full` in any other
call (`say`, `answer`, `interrupt`, `cancel`, `unqueue`, a timer): the call
commits as it would, and the owner stream is closed `lagging`
(`Host::close_stream(o, "lagging")`), `stream/o` and `live/<session>` deleted
and `o` dropped from `streams`, in that call. Later pushes of the session go
nowhere until the next `attach`.

AC7. **Ready.** New `Kernel::stream_ready(&mut self, stream: &str) ->
Called<()>`: for an owner stream (`stream/<id>` kind `owner`), it calls
`Host::resume_stream(t)` for the session's live provider stream, reading no
session record. Unknown ids change nothing.

AC8. **Owner stream ended.** New `Kernel::stream_ended(&mut self, stream:
&str) -> Called<()>` (the producer side's `ended`): when `stream/<id>` is of
kind `owner` and `live/<session>` still names it, it deletes both keys,
drops the id from `streams`, and resumes the session's provider stream
(`Host::resume_stream`); later entries are stored and not pushed. For a
`replaced` stream (no `stream/` key) it changes nothing (case 51's kernel
part: the `ended {replaced}` of an old stream leaves the new one live).

AC9. **Restart.** After a restart, `live/<session>` and owner `stream/`
keys of the older boot are deleted by R4 (as today); a call's pushes for that
session go to no stream; `attach` works as AC1.

AC10. **Delete.** `delete` closes a live owner stream (`close_stream(o,
"closed")`) and deletes its keys as today.

## Interface

Takes from S26-2 (fixed): `Host::open_stream`, `Host::cancel_stream`,
`Kernel::provider_item`, `stream/<id>` `{session, kind}`.
Adds (fixed): `Host::push(&mut self, stream: &str, value: Value) ->
Result<(), Full>`, `Host::close_stream(&mut self, stream: &str, outcome:
&str)`, `Host::resume_stream(&mut self, stream: &str)`; `FakeHost` gains
`full: BTreeSet<String>` (a push to a stream in it fails `Full`) and logs
`HostCall::Push { stream, value }`, `HostCall::Close { stream, outcome }`,
`HostCall::Resume { stream }`; `Full`, `Item`, `Attached`; `Kernel::attach`,
`stream_ready`, `stream_ended`; `provider_item` returns `Called<Item>`. The
rollback of AC5 may be built in `quota.rs`'s `Metered` (buffered writes,
committed or dropped at the end of the call) or in `state.rs`; S26-3's code
must keep passing.
