## Goal

The first tab no longer freezes with no word when Alice opens the same session in a second tab
(PLAN "Stage B carry list", S32 user-sim "felt wrong"). Today `console/kit/kernel.ts` returns on an
`ended {replaced}` and leaves the first tab showing a transcript that silently stops moving. After this
task the first tab says, in one line above the composer (a `role="status"` notice, not an alert), "This
session is open in another tab." with a button "Use here", which attaches again (and so replaces the
other tab, which then says the same). While the notice shows, the composer, Stop and the ask buttons of
that tab are off (a click there would act on a stream this tab no longer reads), and the status line keeps
its last word.

## Acceptance

AC1. A fake kernel whose attach stream ends `replaced`: the session view shows the notice
     "This session is open in another tab." and a "Use here" button; no reattach starts by itself (the
     fake counts one attach).
AC2. "Use here" attaches again with `after` = the last index shown (the fake sees the second attach and
     its `after`), the notice goes away once that attach syncs, and entries pushed after it show once.
AC3. While the notice shows, Send, Stop, and each open ask's Allow once / Allow … this session / Deny… are
     disabled (`disabled` attribute); after "Use here" they are enabled again.
AC4. Switching to another session and back clears the notice (that is a fresh attach).
AC5. Each other ending of the stream (`lagging`, an error) behaves as today (existing tests unchanged).
