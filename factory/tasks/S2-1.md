**Judge account (N10).** Write this, in the file's style:
- The host keeps the judge's key as an account `judge`, as it keeps the OpenAI tokens (5). The
  participant enters the key and the judge's origin (`https://host[:port]`) in the app, on the
  page the manager shows for that checked provider, never in the provider's own page. The app
  stores it in `<home>/app/accounts/judge/<provider mod id>.json` (0600, written atomically).
- A request `https-stream.start` with `account: "judge"` is refused before a byte leaves
  (`destination`) unless the caller is the provider the key was entered for, the method is
  `POST`, and the URL's origin is exactly the account's origin and is in the provider's
  `[http]`. The host adds `Authorization: Bearer <key>`; no redirects (as 5). Without an entered
  key: `no-account` (a new code in 12 for https-stream). A judge call that fails this way is a
  verdict `unsafe` (10), so a missing or wrong key denies.
- Entering the key in the app is the participant's consent for that provider; there is no
  per-origin-client consent for the judge account (8 is unchanged).
- The provider's own page keeps only the judge URL and the thresholds (10, "Settings").
- 14: "No mod sees a credential" now includes the judge's key; a new row "A judge key goes only
  to its judge" holds by the account binding (5).
