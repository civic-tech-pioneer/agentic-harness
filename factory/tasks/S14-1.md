## Goal

The Claude adapter (`kernel/src/adapters/claude.rs`) reads every item strictly and never turns a
doubtful item into an ask. A line that is not UTF-8 becomes `unknown` without any lossy decoding;
a line with a duplicate top-level key becomes `unknown` (the same rule the host uses, 4.5, so the
kernel and the host never read one line two ways). An `ask` or `check` item without `input`, or one
that reuses the `id` of an ask or check still open in the adapter, becomes `unknown` and leaves the
open one untouched (S12 RISKs 2 and 3). A finished `thinking` block that repeats the deltas already
streamed is not pushed live a second time (S12 polish), while the message's `thought` stays as S12
built it.

Already done by S12, keep as is (each has a fixture or test today): an ask/check item with a bad
`tool_use_id` or `expires-at` is `unknown` (`tests/fixtures/adapters/claude/asks.json`); `wrapped`,
`verdict`, `checking` are `unknown` on every stream (asks.json; there is no `direct: false` stream
yet); hook and progress lines give nothing (`ac7_hook_and_progress_lines_give_nothing`).

## Acceptance

AC1. `line(b"{\"type\":\"initialized\"}\xff", 1)` gives exactly one `unknown` entry whose body is
     `{"raw": "{\"type\":\"initialized\"}\\xff"}`: the valid UTF-8 runs as they are, each byte that
     is not valid UTF-8 written as the four characters `\xNN` (lower-case hex). The adapter's source
     contains no `from_utf8_lossy` (a test greps `src/adapters/` for it). A line of only invalid
     bytes `b"\xff\xfe"` gives raw `"\\xff\\xfe"`. Nothing in such a line is parsed: a line
     `b"{\"type\":\"ask\",...valid ask...}\xff"` is `unknown`, never an ask.
AC2. A line that is one JSON object with a duplicate top-level key is `unknown` with raw = the line
     as a string, whatever its type: e.g. a valid ask item with `"tool_use_id"` twice, or
     `{"type":"ask","type":"assistant",...}`. Duplicates only below the top level do not count
     (a `tool_use` whose `input` object has a duplicate key is read as today).
AC3. An `ask` or `check` item whose `input` key is absent, or `null`, is `unknown` (raw = the item),
     and nothing is recorded as open: a later `ask-resolved` for its id is `unknown`.
AC4. An `ask` or `check` item whose `id` equals the `id` of an ask or check that is open (pushed and
     not yet resolved by `ask-resolved`) is `unknown` (raw = the item). The open one is unchanged: its
     later `ask-resolved {by:"expired"}` repeats the first ask's body, not the second's. After that
     resolution the id is free again: a new valid ask with it is an ask.
AC5. Thinking, live: a `thinking` block that arrives after one or more `thinking_delta`s of the same
     step (deltas since the last block, as `Thinking.deltas` tracks today) gives no update and no
     entry. A `thinking` block with no deltas before it is pushed as one `agent_thought_chunk` as
     today. The message `thought` text and `seconds` are as before (the S12 tests
     `ac9_thought_seconds_round_and_clear_at_result` and
     `ac9_thinking_blocks_join_with_a_blank_line_and_replace_their_deltas` pass unchanged).
AC6. Each of AC1–AC5 has a golden fixture input in `tests/fixtures/adapters/claude/` (extend
     `asks.json` and `thinking.json`, or add `strict.json`; a fixture's `line` may need to be a raw
     string: if the harness cannot express non-UTF-8 or duplicate keys, cover those by unit tests in
     `tests/it/adapters.rs` instead and say so). `ac10_never_panics_on_random_input` still passes.
