## Goal

Alice sees delegation and limits in the console (sketch outcomes 1 and 3; TECHNICAL 18.3 `child`
row, 18.5 `idle {stopped}` row; FUNCTIONAL AGT-F-47). A `child` entry shows as a link beside the
parent's tool call with the same `toolCallId`; activating it opens that child session's transcript
through the standard session calls, live and after a reload. A turn stopped at a limit says which
one, and a usage clear empties the context meter.

## Acceptance

AC1. A transcript with a tool call `c1` and a later entry `{"kind":"child","body":{"session":"s9",
     "toolCallId":"c1"}}` renders a link (an `<a>` or button with an accessible name naming the
     child, e.g. "Open child session") inside or directly beside the `c1` tool row; two children of
     two calls render one link each beside their own call.
AC2. Activating the link selects session `s9` in the console exactly as picking it in the sidebar
     does (attach, transcript, status line), with no call outside 2.3; a child id the kernel
     refuses (`unknown-session`) shows the ordinary error and leaves the current session open.
AC3. The same links show after a reload (from replayed entries) and arrive live (from a pushed
     entry), with no doubled link.
AC4. A `child` entry whose `toolCallId` matches no tool row renders as its own row with the link
     (never dropped), so nothing the kernel reports is hidden.
AC5. `idle {stopped {limit: "max-turns"}}` (and `max-tool-errors`, `max-tokens`) shows "Stopped at
     the max-turns" etc. in the status line and the turn-end line (existing 18.5 row; a test pins it
     per limit).
AC6. A `usage` push `{"context-used":null,"context-window":null}` clears the context meter (no stale
     value shown); a later sample shows again.
AC7. `npm test` in `console/` passes; `ui/` is rebuilt by the console build (never by hand).
