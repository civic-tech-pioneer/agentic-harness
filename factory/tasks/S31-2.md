## Goal

A session allow is a thing the kernel holds and can take back. When a Claude
ask is stored, the kernel (never the adapter or the provider) sets its
`reach`: the session allow `{"allow":true,"for":"session"}` would add, or none.
The owner's `answer` with `for: session` adds that reach to the session's
`allows` with an id, writes an `allow` entry (`given: true`), and sends the
host only `{"allow":true}`, never `for` (so `claude` never gets a rule it
would keep). `take-back` removes the allow and writes an `allow` entry
(`given: false`). S31-3 then answers later matching asks from these allows.

This task builds the stricter option of the PLAN's Waiting item "Session
allow on `Bash`" (option (a)): an allow on `Bash` holds only that exact
command, and only when the command passes the 4.1 allow grammar.

Spec (quoted):
- 9.6: "**Session allows.** An answer `{allow, for: session}` adds a rule to
  the session's `allows`: the tool's name, and for a file tool the workspace
  it is in (`Edit(<workspace>/**)`). The rule names that reach for the page.
  The kernel keeps it; it never sends it to `claude` as a rule
  (`updatedPermissions`), so it can be taken back. Later asks that match an
  allow are answered `allow` by the kernel, with `by: session-allow`.
  `take-back` removes the allow, writes an `allow` entry, and later matching
  calls ask again. Allows end with the session."
- 9.3 caps: "`allows` | at most 64 session allows and 64 KiB in all, each at
  most 1 KiB | an answer `for: session` is refused `too-large(65536)`; the
  ask stays open"
- 9.4: "`allow` | `{"id":"<allow id>","reach":"<rule>","given":true|false,"by":"<who>"}`:
  a session allow given or taken back (9.6)"; "`reach` is the session allow
  that `{"allow":true,"for":"session"}` would add (9.6); it is absent when
  none is offered (a check, an `agent:` owner)."
- 2.3: "`allow` in `take-back` is the id of an `allow` entry (9.4)";
  `take-back: func(session: string, allow: string) -> result<_, error>`;
  error `unknown-allow`.
- 9.3 "Past" (this task changes what calls write; hold to it): "*Refused
  `quota` when past:* `start`, `say` (whether it starts a turn or queues), an
  `interrupt` replacement, `rename`, an `answer` with `for: session`. Not
  refused: `answer` without `for: session`, `interrupt` without a
  replacement, `cancel`, `unqueue`, `delete`, `read`, `list`, `queued`, the
  restart step, timers." and "*Any call when past* (...): an ask decision and
  the host's `ask-resolved` are stored (short, 9.4); (...) a new ask is not
  stored and is denied at once (`Request::Answer` deny, reason `quota`); any
  other entry is not stored."

Decisions the foreman made (build them as written):
- **reach** (pure, `kernel/src/broker.rs`): none for a `check`, for an owner
  whose identity starts `agent:`, and for `AskUserQuestion` and
  `ExitPlanMode` (they ask the person for content). For the file tools
  `Read`, `Write`, `Edit` (`file_path`), `NotebookEdit` (`notebook_path`),
  `Glob`, `Grep` (`path`): `<Tool>(<ws>/**)` when the record's `workspace` is
  `Some(ws)`, `ws` starts with `/`, does not end with `/`, has no `(`, `)` or
  control character, and the input's path is a string that starts with
  `<ws>/` and has no empty, `.` or `..` segment; else none (an absent `path`
  of `Glob`/`Grep` is none). For `Bash`: `Bash(<command>)` with `command`
  the input's `command` string exactly (no trimming), offered only when that
  rule passes the 4.1 allow grammar (`profile.rs` `rule_problem(rule, true)`
  is `None`; make it `pub(crate)`) and the command has no `:` at all (so it
  never reads as a `:*` prefix rule); else none. Any other tool: its name,
  when the name passes `rule_problem(name, true)`; else none.
- The kernel sets the ask body's `reach` itself when it stores a new
  (undecided) Claude ask, replacing or removing any `reach` the incoming body
  carries. A decided ask entry is stored as today.
- `Record.allows` becomes `Vec<Allow>`, `Allow { id: String, reach: String }`
  (serde as `{"id","reach"}`); the caps count each allow's serialized JSON.
  No migration (nothing is deployed).
- The allow id is the decimal index `i` of its `given: true` entry.
- The owner's `answer` with `for: session` on an ask with a `reach`: when an
  allow with an equal `reach` is held, adds nothing and writes no `allow`
  entry; else adds it (caps as 9.3) and writes
  `{"id":"<i>","reach":"<reach>","given":true,"by":"owner"}`. The pending
  answer keeps `for: session` as today. `Request::Answer`'s decision drops
  `for` (`{"allow":true}`, with `input` when the decision has one).
- `take-back(caller, session, allow)`: owner checks as `answer`
  (`not-owner`, `unknown-session`); an id not in `allows` is
  `unknown-allow`, writing nothing; else removes it and writes
  `{"id":"<id>","reach":"<reach>","given":false,"by":"owner"}`, pushed live
  as every entry. It reads no `access/` (it only narrows) and is never
  refused `quota`: past quota it still removes and writes its entry, charged
  like the calls that cannot fail (`finish_as(.., true)`), so its write is
  bounded (one entry of at most ~1.1 KiB per held allow). A repeat of the
  same call is `unknown-allow`. Fix `UnknownAllow`'s message to name a
  session allow, not a pending ask.

## Acceptance

AC1. reach, pure (unit tests on `broker::reach`): `Edit` of `/w/a/b.rs` in
workspace `/w` -> `Edit(/w/**)`; `/w2/x`, `/w/../x`, `/w/./x`, `/w//x`,
`w/x`, a non-string path, and any file tool with `workspace: None` -> none;
`NotebookEdit` reads `notebook_path`, `Glob`/`Grep` `path`; `Bash` with
`npm test` -> `Bash(npm test)`; `Bash` with `rm -rf /tmp/x; ls`, `ls | wc`,
`python3 x.py`, `npm run x`, `curl a:b`, `ls\nrm x`, `""`, `ls *:*` -> none;
`WebFetch` -> `WebFetch`; `mcp__watane__send` -> `mcp__watane__send`;
`AskUserQuestion`, `ExitPlanMode`, a `check`, an owner `agent:x`, a tool name
with a space -> none.

AC2. An ask stored through `provider` gets the kernel's `reach` in its entry:
a `Bash` ask `npm test` has `"reach":"Bash(npm test)"`; an Out entry whose
body carries `"reach":"Bash"` for a `Bash` ask `ls | wc` is stored with no
`reach`.

AC3. Owner `answer {allow, for: session}` on that ask: `Record.allows` is
`[{"id":"<i>","reach":"Bash(npm test)"}]` where `<i>` is the index of a new
entry `{"kind":"allow","body":{"id":"<i>","reach":"Bash(npm test)","given":true,"by":"owner"}}`;
the host got `Request::Answer` with decision exactly `{"allow":true}`. A
second ask with the same command answered `for: session` adds no allow and
no entry.

AC4. `take_back` with that id: `allows` is empty, an entry
`{"id":"<i>","reach":"Bash(npm test)","given":false,"by":"owner"}` is
written and pushed to an attached owner stream; again with the same id:
`unknown-allow`, nothing written; another owner: `not-owner`; an unknown
session: `unknown-session`.

AC5. Past quota (owner over its byte cap): `answer for: session` is refused
`quota` (unchanged); `take_back` succeeds and writes its entry.

AC6. Caps (9.3): the 65th allow, an allow over 1 KiB (a long workspace
path), or one past 64 KiB in all: `answer for: session` is
`too-large(65536)`, writes nothing, sends nothing, the ask stays open.

AC7. An ask whose `reach` is absent: `answer for: session` is refused
`{field: "decision"}` (unchanged).

AC8. `cargo test`, `cargo clippy --all-targets -- -D warnings`,
`cargo fmt --check` and `factory/gate.sh` pass.

## Interface

Provides (fixed) to S31-3:
```rust
// kernel/src/broker.rs, `pub mod broker;` in lib.rs
pub fn reach(owner: &str, workspace: Option<&str>, kind: &str, tool: &str, input: &serde_json::Value) -> Option<String>;
// kernel/src/record.rs, re-exported from lib.rs
#[derive(Serialize, Deserialize, Clone, Debug, PartialEq, Eq)]
pub struct Allow { pub id: String, pub reach: String }
impl Record { pub fn add_allow(&mut self, a: Allow) -> Result<(), KernelError>; }
// kernel/src/sessions.rs
impl Kernel { pub fn take_back(&mut self, caller: &str, session: &str, allow: &str) -> Result<Called<()>, KernelError>; }
```
The stored ask entry's body has `reach` iff `broker::reach` gave one.
