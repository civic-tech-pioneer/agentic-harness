Slice: S11 — a kernel maker runs `cargo test` in `kernel/` and sees a session's transcript stored and read back as 9.4 and 9.1 say, against an in-memory key-value state of host 7's shape (get, put, delete; 4 MiB per value; no prefix scan), for transcripts of 10 and of 10 000 entries.

## Goal

Two new modules of the `agent-kernel` crate. `kernel/src/state.rs`: the kernel's view of host
state (host 7) as a small trait (`get`, `put`, `delete`; no prefix scan) and an in-memory
implementation that refuses a value over 4 MiB and counts the gets, puts and bytes, so tests can
prove what a call touched. `kernel/src/transcript.rs`: a session's transcript (9.4) stored in
chunks `entries/<session>/<n>` (9.1). It appends entries with indexes from 1, cuts an entry over
256 KiB into `part` entries, reads pages forwards and backwards, makes the replay decision of
`attach` (entries, or `behind`), reads an unknown entry as `unreadable`, and gives readers a
joiner that turns parts back into the whole entry. Pure logic over the trait: no clock, no
streams, no session record of its own (the caller owns the `chunks` and the high-water index,
which the session record of 9.3 embeds later).

## Acceptance

AC1. State (`state.rs`): `MemState` implements `State`. `put` of a value over 4 MiB (4 194 304
     bytes) returns `Err(TooLarge(4194304))` and stores nothing; `get` of a missing key is `None`;
     `delete` of a missing key is fine. `MemState::counts()` returns the gets, puts, deletes, bytes
     read and bytes written since the last `reset_counts()`, and `MemState::get_keys()` the keys
     read in order (tests assert on both).
AC2. Append, indexes: on a new transcript (`Meta::default()`), appending 10 entries gives them
     `i` 1..=10 in order; each stored entry is one line of JSON
     `{"v":1,"i":k,"kind":…,"at":…,"uuid"?:…,"body":…}` (key order as written, `uuid` only when
     given). `append` returns the index of the whole entry (for a large one, its last part's).
AC3. Chunks (9.1 as on main: at most 256 entries and at most 64 KiB, or exactly one entry when
     that entry is over 64 KiB): an append that would take the last chunk past 64 KiB or past 256
     entries, or an entry over 64 KiB, or a last chunk holding one entry over 64 KiB, starts a new
     chunk; `meta.chunks` gets the new chunk's first index. Tests: after any sequence of appends,
     every stored chunk satisfies the rule and `meta.chunks` lists each chunk's first index
     ascending; 300 entries of 10 bytes give chunks of 256 and 44 entries; an entry of 100 KiB has
     a chunk of its own and the next small entry starts another.
AC4. Append cost (case 55): appending a 4 KiB entry to a transcript of 10 and of 10 000 entries
     puts exactly one value, of at most 64 KiB + the entry's line, and gets at most one chunk (the
     last); chunks before the last are never written again (a test snapshots them and compares
     after 1 000 more appends). The bytes read plus written by that append differ by at most 10%
     between 10 and 10 000 entries (TECHNICAL 17, stage B budget "within 10%").
AC5. Parts (9.4): an entry whose serialization is over 262 144 bytes is stored as consecutive
     `part` entries `{"v":1,"i":k,"kind":"part","at":…,"body":{"n":1..m,"m":m,"text":"<slice>"}}`,
     each part's serialization at most 262 144 bytes, `text` cut at UTF-8 character boundaries;
     the joined `text` is the serialization of the whole entry, whose `i` is the last part's
     index. Tests use entries of 3 MiB of ASCII, of multi-byte text (é, 😀) and of text full of
     `"` and `\n` and control characters (which grow when escaped); for each, joining gives the
     whole entry byte for byte with `i` = the last part's index. An entry of exactly 262 144 bytes
     is not split.
AC6. `read(after, before, max)` (9.4): returns `Page { entries: Vec<String>, last }`, ascending.
     Without `before`: the oldest entries with `i > after`; with `before = Some(b)`: the newest
     with `after < i < b`. At most `max` entries (`max` 0 is taken as 1, over 256 as 256) and at
     most 2 MiB (2 097 152 bytes, the sum of the entries' lengths), but never fewer than one entry
     when one exists in range (every page makes progress). `last` is the high-water index (0 for
     an empty transcript). A test pages forwards through 10 000 entries with `max` 256 and
     another backwards with `before`, and each gets every index exactly once.
AC7. An `after` inside a part group (9.4): when `after` is the index of a part whose `n` is
     less than its `m`, the read starts at the group's first part (`after` is moved to the index
     before that part). The same holds for `before` reads. A read whose page ends inside a group
     is fine; `Joiner` joins across pages (AC10).
AC8. Chunk reads (9.4 "Chunk reads", case 55): a read touches only the chunks that hold its
     range, found from `meta.chunks` (binary search), plus at most one more chunk at the end to
     learn that its entry does not fit. Tests count the gets: `read(9_990, None, 5)` on 10 000
     entries of 100 bytes gets at most 2 chunk keys; a forward page of 256 small entries gets at
     most 3; a backward page `read(0, Some(5_001), 10)` gets at most 2. No read gets a key that is
     not a chunk of that session. The bytes a page reads stay within 2 MiB + 320 KiB.
AC9. Replay decision (`replay(after)`, 9.4): with at most 128 entries and at most 2 MiB after
     `after` (the start moved as AC7), returns `Replay::Entries(Vec<String>)` (all of them,
     ascending); otherwise `Replay::Behind { through: last }`, where 129 or more entries after
     `after` decides it without reading any chunk. Tests: 128 small entries -> `Entries`; 129 ->
     `Behind` with 0 gets; 10 entries of 250 KiB -> `Behind` (over 2 MiB); after the newest index
     -> `Entries(vec![])`.
AC10. `Joiner` (the reader of 9.4): fed the entry strings of one or more pages in ascending
     order, it yields whole entries as `serde_json::Value`: a non-part entry as is, a part group
     once all its parts arrived, as the parsed join. A group split across two pages, read
     forwards, joins byte for byte. A part whose `n` does not follow the previous part, or a
     non-part entry in the middle of a group, drops the incomplete group (the client then reads
     from the group's start again) and never panics.
AC11. Unreadable (9.4): a stored line of an unknown `kind`, a `v` above 1, or text that is not
     a JSON object, reads (in `read` and `replay`) as
     `{"v":1,"i":k,"kind":"unreadable","raw":"<the stored line as a string>"}` and keeps its `i`
     (from the line when it has a numeric `i`, else from its position). Known kinds:
     `message`, `tool`, `ask`, `allow`, `verdict`, `turn`, `compaction`, `unknown`, `part`. A test
     writes such lines straight into a chunk through `State` and reads them back.
AC12. Limits: `meta.chunks` at 16 384 entries and a new chunk needed -> `append` returns
     `Err(KernelError::Quota)` and writes nothing (9.3, `chunks` cap). Nothing panics on a
     missing chunk key (it reads as no entries in it, and the test says so).
AC13. Errors: `KernelError::Behind` displays `behind: <n> entries stored, page with read`
     (9.4: `through` is the high-water index, not a compaction); the code stays `behind`.
     `cargo test` and `cargo clippy --all-targets -- -D warnings` pass in `kernel/`; the default
     `cargo test` stays under 10 s on this machine (the 10 000-entry tests use small entries).

// kernel/src/state.rs
pub const MAX_VALUE: usize = 4 * 1024 * 1024;
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct TooLarge(pub usize);                 // the limit in bytes
pub trait State {
    fn get(&mut self, key: &str) -> Option<Vec<u8>>;   // &mut: a counting state counts reads
    fn put(&mut self, key: &str, value: Vec<u8>) -> Result<(), TooLarge>;
    fn delete(&mut self, key: &str);
}
#[derive(Debug, Default, Clone, Copy, PartialEq, Eq)]
pub struct Counts { pub gets: u64, pub puts: u64, pub deletes: u64, pub bytes_read: u64, pub bytes_written: u64 }
#[derive(Debug, Default)]
pub struct MemState { /* BTreeMap<String, Vec<u8>>, counts, keys read */ }
impl MemState { pub fn new() -> Self; pub fn counts(&self) -> Counts; pub fn reset_counts(&mut self);
                pub fn get_keys(&self) -> &[String]; pub fn len(&self) -> usize; }

// kernel/src/transcript.rs
pub const CHUNK_BYTES: usize = 64 * 1024;      pub const CHUNK_ENTRIES: usize = 256;
pub const ENTRY_BYTES: usize = 256 * 1024;     pub const PAGE_BYTES: usize = 2 * 1024 * 1024;
pub const PAGE_ENTRIES: u32 = 256;             pub const REPLAY_ENTRIES: u64 = 128;
pub const MAX_CHUNKS: usize = 16_384;
#[derive(Debug, Clone, Default, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "kebab-case")]
pub struct Meta { pub chunks: Vec<u64>, pub last: u64 }   // the session record's fields (9.3)
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct NewEntry { pub kind: String, pub uuid: Option<String>, pub body: serde_json::Value }
impl From<crate::adapters::Entry> for NewEntry { /* kind as its lowercase name */ }
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Page { pub entries: Vec<String>, pub last: u64 }
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Replay { Entries(Vec<String>), Behind { through: u64 } }
pub struct Transcript<'a, S: State> { /* state, session id, meta */ }
impl<'a, S: State> Transcript<'a, S> {
    pub fn new(state: &'a mut S, session: &str, meta: &'a mut Meta) -> Self;
    pub fn append(&mut self, entry: &NewEntry, at: u64) -> Result<u64, KernelError>;
    pub fn read(&mut self, after: u64, before: Option<u64>, max: u32) -> Page;
    pub fn replay(&mut self, after: u64) -> Replay;
}
pub fn chunk_key(session: &str, n: usize) -> String;   // "entries/<session>/<n>", n = position in meta.chunks, from 0
#[derive(Debug, Default)]
pub struct Joiner { /* the open group */ }
impl Joiner { pub fn new() -> Self; pub fn push(&mut self, entry: &str) -> Option<serde_json::Value>; }
