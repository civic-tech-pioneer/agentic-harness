## Goal

`design/TECHNICAL.md` section 18 states what S7 decided and found: the Place rule as the
adversary narrowed it (focus in an open ask's card stops the follow at any scroll position; Needs
you ends the follow; only the "New activity below" pill, or focus leaving the card, resumes it;
a pointer press on the transcript's scrollbar or on non-focusable text of the card does not
resume it either, S7 RISK a); 18.2 says the reducer's view is what the transcript draws and the
assistant-ui runtime holds the newest rows only; and P14's rules and numbers are written down.
This is a documents-only task: the code for RISK (a) and the highlight budget come in S23; the
spec leads.

## Acceptance

AC1. 18.6 "Place" says, in this project's plain style: the transcript follows new output only
     while the reader is within 40 px of the end and focus is not inside a card with an open ask;
     while focus is inside such a card it does not follow, whatever the scroll position; Needs you
     ends the follow; the "New activity below" pill returns to the end and resumes it, and so does
     focus leaving the card (as S7-fix3 built: check `console/kit/thread.tsx` and
     `console/src/follow_S7_fix3.test.tsx` for the exact resume conditions and state them, no
     more); a pointer press on the transcript's scrollbar or on non-focusable text inside the
     card is not focus leaving the card and does not resume the follow (S7 RISK a; S23 builds
     it). The existing sentence about session rows and the pointer stays.
AC2. 18.2 "State" says the console's reducer view is the state the transcript draws; the
     External-store runtime is fed only the newest rows (100 today, `console/` — check the
     number in code) and nothing reads its messages; dropping the runtime is open (the human's
     call, PLAN). The existing facts of the bullet (the wire of 9.4, `wire.ts`, `reduce.ts`, the
     ACP adapter) stay.
AC3. 18.6 gains a "**Long sessions.**" bullet (or 18.7 a row; pick one and say why in the
     commit message) with P14's rules and numbers, each checked against the code it cites:
     - the transcript is windowed: at most about 120 rows mounted (`console/kit/thread.tsx`,
       `kit/window_S7.test.tsx`), and rows with focus or an open ask or check stay mounted;
     - the page is told at most once per animation frame (a 16 ms timer where there is none,
       `console/kit/kernel.ts`);
     - code is highlighted once its block is complete and visible, off the main thread or within
       a time budget per block, past which the block stays plain; a block over 64 KiB stays
       plain (`kit/parts/highlight.ts`);
     - the reducer's cost per message does not grow with the transcript's length;
     - the large-transcript fixture runs in `npm test` (`console/src/long_S7.test.tsx`): 5 000
       entries, the stream at 50 deltas/s, p95 over 20 samples: input ≤ 50 ms, Stop ≤ 100 ms,
       scroll ≤ 100 ms, stream ≤ 100 ms, the end shown ≤ 2 s after open.
     Copy the numbers from the test file, not from this brief, if they differ.
AC4. 18.7's View row (or the new row) names the long fixture, so the Tests table points at it.
AC5. No other section changes. Section 14 changes only if a boundary row is wrong after the
     edit (it should not be: the console row names `console/`, `ui/` already). In particular 9.3

AC6. `factory/gate.sh` passes (its link and docs checks; `.claude/factory/check-docs.sh` if it
