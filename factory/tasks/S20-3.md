## Goal

The owner can interrupt a turn (with or without a replacement) and cancel a
session, and every call that would give a session more work reads
`access/` again, so a client that lost a profile cannot keep a session
working on it (9.7 "Revoking", case 74). `cancel` closes every open or
pending ask with one decision each (case 73 (g)). An OpenAI profile without
`model` is refused. `.gitignore` keeps build folders out, and a refusal
without backend and model prints its field and reason cleanly.

## Acceptance

AC1. `Kernel::interrupt(caller, session, replacement: Option<&str>) -> Result<Called<()>, KernelError>`
(2.3): owner checked, R6 lazy step first. With no replacement: an active
turn (`running`, `waiting`, `paused`) ends `idle {interrupted}` (a `turn`
entry, pushed), open and pending asks are left as they are (the host closes
them; 9.3 R4 idle row), no queued input starts, the session leaves
`active/` (A2), and the kernel sends a new `Request::Interrupt { session }`.
On `idle`, `unknown`, `resume-lost` it changes nothing and returns `Ok`.
With a replacement: `check_input` first (`too-large(262144)`), the access
check of AC3, then the same end, then the replacement starts a turn as
`say` on `idle` does (a user `message` entry, `running`, `Request::Turn`,
`resume: false`); the session stays in `active/` (one page write at most,
A2). All refusals come before the first write.

AC2. `Kernel::cancel(caller, session) -> Result<Called<()>, KernelError>`:
owner checked, R6 first; `close_all(.., "cancel", ..)` (S20-2) writes one
decision per open or pending ask in any turn state; an active turn ends
`idle {interrupted}`; no queued input starts and the queue is kept; the
session leaves `active/`; the kernel sends `Request::Cancel { session }`.
Children: none are built; leave a one-line comment. Never refused for
access.

AC3. **Revoking** (9.7): a private `fn may_use(&mut self, owner, profile) -> bool`
shared with `start` (absent or unreadable `access/<owner>` allows none).
Refused `refused` with one refusal `{field: "profile"}`, writing nothing, when
the session's profile is not in `access/<owner>`: `say` (whether it would
start a turn or queue; R5 Continue on `unknown` included), `interrupt` with
a replacement, `answer` with `allow` (with or without `for`). Checked after
the key replay and the owner check, before the first write. Not refused:
`read`, `list`, `queued`, `unqueue`, `rename`, `answer` with `deny`,
`interrupt` without replacement, `cancel`, `delete`. **A turn's end**: when
a provider turn change ends a turn with inputs queued, the next input
starts only if the profile is still in `access/<owner>`; otherwise the turn
ends as it would and the queue is kept (and its `queue` push is not sent).
A child session's check against its root is out of scope (no children yet).
