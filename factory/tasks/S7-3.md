## Goal

Code in an agent's message shows as a code block, highlighted with Shiki (its JavaScript regex
engine, 18.2), and the highlighting costs nothing while it cannot help: a block is highlighted
only once it is complete (its closing fence arrived, or the message is finished) and visible
(in or near the viewport), and only once per (language, code). Until then it shows as plain
monospace text, the same size, so nothing jumps when the colours arrive.

## Acceptance

AC1. An agent row's text is split into prose and fenced code blocks (```lang ... ```). Prose shows
     as today (plain text, whitespace kept as today). A block shows as `<pre class="wa-code"><code>`
     in JetBrains Mono, with its language as a small label when one is given. No other Markdown
     is parsed (out of scope).
AC2. Complete and visible: a block whose closing fence has not arrived while the message is
     `writing` stays plain, even when visible. A complete block outside the viewport (an
     `IntersectionObserver`, with a margin of one viewport) stays plain until it comes near. The
     test drives both: a streaming message with an open fence calls the highlighter 0 times;
     closing the fence while visible calls it once; a complete block never intersected calls it
     0 times.
AC3. Once: highlighting the same (language, code) again (a re-render, the row leaving the window
     and coming back, a second identical block) does not call Shiki again (a module-level cache,
     bounded: at most 200 entries or 2 MiB of code, oldest out).
AC4. Shiki: pinned exact version in package.json and the lockfile; `shiki/core` with
     `createJavaScriptRegexEngine` (no WebAssembly, no Oniguruma); languages and the two themes
     (light and dark, matching the frames' tokens of 18.4) loaded as same-origin chunks by dynamic
     import, only when a block of that language is first highlighted; an unknown or absent
     language stays plain. `test/build.test.ts` passes on the new build (no `eval`,
     `new Function`, WebAssembly or outside URL); if Shiki's bundle trips a check, the check is
     not loosened: pick another import path or report it.
AC5. The languages offered at least: ts, tsx, js, jsx, json, bash/sh, rust, python, toml, yaml,
     diff, html, css, md. A block over 64 KiB of code is not highlighted (stays plain).
AC6. Highlighted HTML is rendered from Shiki's token output (`codeToTokens` or the hast output)
     as React elements, never through `dangerouslySetInnerHTML` (a test asserts code text with
     `<img src=x onerror=...>` shows as text and adds no element).
AC7. `npm test`, `npm run typecheck`, `factory/gate.sh` pass with `ui/` rebuilt and committed;
     `npm run build` reports the main chunk size before and after in your report (the languages
     must not be in the main chunk).
