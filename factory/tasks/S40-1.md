## Goal
The OpenAI loop's wire history exists as pure, tested code: the items a session sends to the
Responses API are stored in `wire/<id>/<n>` chunks, repaired before each request (an orphaned call
gets `aborted`, an output without a call is dropped), turned into a request body whose prefix never
moves between ordinary steps, trimmed by the body budget, and cut at the newest compaction item or
summary (the active history). Nothing here calls the host; the loop (S40-3) calls these functions.

## Acceptance
AC1 (case 1) `repair`: a `function_call` with no `function_call_output` gets one, `{"type":"function_call_output","call_id":c,"output":"aborted"}`, placed right after the last call of its step; an output whose `call_id` no call has is dropped; call order is kept; a `reasoning` item without `encrypted_content`, or made by another model than the request's, is dropped, and a kept one is sent without its `id`.
AC2 (case 2) Two ordinary steps: the second request body's `input` begins with the first body's `input`, byte for byte (serialise both, compare the prefix), and `instructions` is identical.
AC3 (case 40, trimming) A history whose body passes 896 KiB: the mark is set at the first item of the last 4 steps; items before it lose `encrypted_content` reasoning oldest first, then tool outputs are cut to 8 KiB with the marker ` [cut by watane: <n> bytes]` appended, until the body is at most 768 KiB; `Trim` records the mark and how far it went; the next 3 requests (one step each, small) send the items before the mark trimmed the same way, so each extends the trimmed one; the mark does not move until a body passes 896 KiB again. Still over 1 MiB with everything before the mark trimmed: `Err(BodyTooLarge)`.
AC4 (case 40, compaction; case 54) Appending a `{"type":"compaction",...}` item moves `active` to its index; the next body's `input` starts at that item; chunks wholly before `active` are deleted in the same call (count the state keys); a request reads no chunk before the one holding `active` (count the reads with `MemState`'s counters).
AC5 (case 40, summary) `restart_from_summary` appends one user message item holding the summary and moves `active` to it; the next body starts there; `instructions` unchanged.
AC6 Chunks: a chunk holds at most 64 KiB of items, or exactly one item over 64 KiB; an append rewrites at most the last chunk plus the new items; `wire_chunks` lists the first wire index of each chunk; `delete_all` removes every `wire/<id>/<n>`.
AC7 Body fields, in this order: `model`, `instructions`, `input`, `tools` (omitted when empty), `tool_choice: "auto"` (with tools), `parallel_tool_calls: true` (with tools), `reasoning` (when given), `include: ["reasoning.encrypted_content"]`, `store: false`, `stream: true`, `prompt_cache_key: <session id>`, `context_management: [{"type":"compaction","compact_threshold":<n>}]`; `compact_threshold` never over 200 000.

```rust
pub const BODY_TRIM_AT: usize = 896 * 1024;   pub const BODY_TRIM_TO: usize = 768 * 1024;
pub const BODY_MAX: usize = 1024 * 1024;      pub const COMPACT_THRESHOLD: u64 = 200_000;
/// One stored wire item: its index, the step that made it (0 for an input), the model that made it.
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct WireItem { pub i: u64, pub step: u64, #[serde(default, skip_serializing_if = "Option::is_none")] pub model: Option<String>, pub item: Value }
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)] #[serde(rename_all = "kebab-case")]
pub enum TrimStage { Reasoning, Outputs }
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)] #[serde(rename_all = "kebab-case")]
pub struct Trim { pub mark: u64, pub through: u64, pub stage: TrimStage }
/// The wire part of `loop/<id>`: S40-3 embeds it in its loop state with `#[serde(flatten)]`.
#[derive(Debug, Clone, Default, PartialEq, Serialize, Deserialize)] #[serde(rename_all = "kebab-case", default)]
pub struct Wire { pub next: u64, pub active: u64, pub wire_chunks: Vec<u64>, pub steps: u64, pub trim: Option<Trim> }
pub struct BodyArgs<'a> { pub session: &'a str, pub model: &'a str, pub instructions: &'a str, pub tools: &'a [Value], pub reasoning: Option<&'a Value>, pub compact_threshold: u64 }
#[derive(Debug, Clone, PartialEq, Eq)] pub struct BodyTooLarge(pub usize);
impl Wire {
    /// Appends items made by `step` (0: an input) with `model`; a compaction item moves `active` (and deletes chunks wholly before it).
    pub fn append(&mut self, state: &mut impl State, id: &str, step: u64, model: Option<&str>, items: Vec<Value>) -> Result<(), KernelError>;
    /// The stored items from `active` on, reading no chunk before the one holding it.
    pub fn active_items(&self, state: &mut impl State, id: &str) -> Vec<WireItem>;
    /// Appends one user message with `summary` and moves `active` to it (9.5: `failed {too-large}`, resume-lost).
    pub fn restart_from_summary(&mut self, state: &mut impl State, id: &str, summary: &str) -> Result<(), KernelError>;
    pub fn delete_all(&mut self, state: &mut impl State, id: &str);
    /// Repair, trim by the budget (updating `self.trim`), and serialise the request body.
    pub fn body(&mut self, args: &BodyArgs, items: &[WireItem]) -> Result<String, BodyTooLarge>;
}
pub fn repair(items: &[WireItem], model: &str) -> Vec<Value>;
pub fn user_message(text: &str) -> Value;   // {"type":"message","role":"user","content":[{"type":"input_text","text":..}]}
```
A step number grows by one per completed response (`steps`); "the last 4 steps" are the items whose `step` is among the 4 highest step numbers present (inputs, step 0, between them count with the step before them: set an input's `step` to the current `steps` when appended).
