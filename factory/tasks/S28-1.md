## Goal

When a Claude session's provider stream ends (`ProviderEvent::Ended`) while
its turn is `running` or `waiting`, the kernel ends that turn
`idle {failed {error: "provider-ended"}}` in the same call, after closing
every open or pending ask as 9.8 rule 4 says. So no stored turn shows
`running` with nothing driving it: the next `say` starts a turn (it no longer
only queues) and resumes the Claude session, and a client offers "Try again"
(18.5, row `idle {failed}`). TECHNICAL 9.3, 9.8 rule 4 and a new case 76 in
section 16 say so. This is the product owner's decision on the S26 RISK
"Stuck session after a crash" (PLAN, Deputy decisions 2026-11-21 S26 RISKs:
"a provider `ended` during an active turn ends it `failed {provider-ended}`").

## Acceptance

AC1. **Ended ends the turn.** A session `running` with a live provider
stream gets `ProviderEvent::Ended` on that stream (`provider_item`): after
the call the record's turn is `idle {stop: failed {error: "provider-ended"}}`,
the transcript's last entry is a `turn` entry with that body, the call pushes
that turn, the session is no longer in `active/` (its `active-page` is
absent), and it holds no `idle` deadline (the stream is already released, 9.3
"As built (S26)": the `idle` deadline is set only "while the session holds a
live provider stream").

AC2. **Asks first, one turn entry.** A session `waiting` on one open ask and
one ask with a pending answer gets `Ended`: the two decision entries of case
73 (f) (`deny, by: kernel, reason: ended` and the pending answer) come
before exactly one new `turn` entry, `idle {failed {provider-ended}}`; no
`turn` entry for `running` is written between them (the waiting turn does
not "follow" to `running` first, as R4 sets its own turn).

AC3. **Past quota too.** With the owner past quota (as `tests/it/s26.rs`
sets it), a `waiting` session that gets `Ended` ends `idle {failed
{provider-ended}}` with exactly one new `turn` entry (it ends an active
turn, so 9.3 Quota stores it: "a turn change is written as an entry only
when it ends an active turn") and its push.

AC4. **The queue waits for a person.** A session `running` with one queued
input gets `Ended`: the turn ends `failed {provider-ended}`, no queued input
starts, the queue keeps its input, and no `Request::Turn` is sent. The next
`say` starts a turn with the oldest queued input first (the new one joins
the queue, as `say` on an idle session already does), sends
`Request::Turn` with `resume: true` (a profile with `persist: false`:
`resume: false`), and opens a provider stream.

AC5. **The next `say` starts a turn.** A session `running` with no queue
gets `Ended`, then `say`: the `say` starts a turn (turn `running`, a user
`message` entry, `Request::Turn {resume: true}`), not a queued input.

AC6. **Inactive turns are unchanged.** `Ended` on a session whose turn is
`idle {completed}`, `unknown` or `resume-lost` leaves the turn as it was and
writes no `turn` entry (it still frees the stream's slot and keys, as S26).

AC7. **The spec says so.** `design/TECHNICAL.md` changed in place, only in
9.3, 9.8 and 16:
- 9.3, the bullet list after the turn-state JSON: a new bullet (after the
  `cancel`/`delete` one) with this rule: "A provider stream's `ended` while
  the turn is `running` or `waiting` closes each open or pending ask (9.8
  rule 4) and ends the turn `idle {failed {error: provider-ended}}` in the
  same call: one `turn` entry (also past quota, since it ends an active
  turn), no `idle` deadline (the stream is gone), and no queued input
  starts; the next `say` starts a turn, the oldest queued input first, and
  resumes the Claude session (as after the idle release; `persist: false`: a
  fresh session). A client offers Try again (18.5). On any other turn,
  `ended` changes no turn."
- 9.8 rule 4, the bullet "at the kernel's own closing steps": after "The
  `ended` closes every open or pending ask or check of the session in the
  same call, so no Claude ask stays without a decision." add "; then it ends
  an active turn `idle {failed {error: provider-ended}}` (9.3)."
- 16: a new case 76 "(9.3, 9.8 rule 4) Kernel crate: the provider stream's
  `ended` on a `running` or `waiting` session ..." stating AC1–AC6 in the
  section's style.
`factory/gate.sh` passes.

## Spec

Quoted rules this task follows (do not paraphrase them in code comments):
- 9.3, turn states: "`idle {stop}` | `completed`, `interrupted`, `stopped
  {limit}` (names the limit), `failed {error}`"; AGT-F-10 (9.3 R4): "no
  stored turn is shown as `running` unless something drives it".
- 9.8 rule 4: "at the kernel's own closing steps: `cancel` and the restart
  step R4 (9.3) and the provider stream's `ended` (3). The entry is the
  pending answer, what the kernel answered ...; an open ask or check with no
  pending answer gets `deny`, `by: kernel`, reason `cancel`, `restart` or
  `ended`. The `ended` closes every open or pending ask or check of the
  session in the same call, so no Claude ask stays without a decision."
- 9.3 Quota, "Any call when past": "a turn change is written as an entry
  only when it ends an active turn (so a turn gets at most one `turn` entry
  past quota ...)" and "no queued input starts while past".
- 9.3 Restart, R4 last row: "a Claude session's provider stream of an older
  boot counts as released, so its next `say` opens a new provider stream and
  resumes with `session {resume}` (`persist: false`: a fresh session), as
  after the idle release".
- 9.3 "The active index", A2: "a call that moves it out removes it from its
  `active-page`".
- 18.5: "`idle {failed}` | Failed, with the cause | triangle | | Try again".

## Interface

Provides to S28-2 (which runs after this task, in the same file): no new
public item. `KernelError`, `ProviderEvent`, `Turn`, `Stop` are unchanged;
the error string is exactly `provider-ended`. Inside `sessions.rs`,
`provider_work` handles `ProviderEvent::Ended` by `close_all_with(..,
"ended", .., follow: false)` and then a turn change to `Turn::Idle { stop:
Stop::Failed { error: "provider-ended".into() }, seconds: None, tools: None,
tokens: None }` that starts no queued input. S28-2 will move the past-quota
flag out of `Kernel`; keep the turn change on the existing `turn_to` path so
that move stays mechanical.
