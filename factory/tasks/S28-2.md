## Goal

The past-quota flag can no longer be read by a call that did not read the
owner's accounts first: the compiler enforces it. Today `Kernel` keeps
`past: bool` from one call to the next, "set by `accounts`", and it is right
only because every call that writes reads the accounts first (S26 RISK
"Carried-over quota flag": "nothing enforces that. A stage D caller
(ask-expiry timers, the OpenAI step rows) must call `accounts()` first"; PO
decision, PLAN Deputy decisions 2026-11-21: "the past-quota flag is made
unreadable without the accounts read (S28)"). After this task the flag lives
only in the value `accounts()` returns, and each function that decides by it
takes that value as a parameter. Also `kernel/tests/it/adv_s26.rs` passes
`cargo fmt --check` (it is no longer red-only). Behaviour does not change.

## Acceptance

AC1. **No carried flag.** `Kernel` has no `past` field (nor any other field
that holds the flag between calls). `grep -n "self.past" kernel/src/` finds
nothing.

AC2. **Only `accounts()` makes it.** The flag is a field of the `Acct` that
`accounts()` returns (or a `Past` type held in it) that code outside
`accounts()` cannot construct or set: a private field set only in
`accounts()`, read through a method. Each function that reads the flag
today (`append_loose`, `turn_to`, `change_turn`, and any other that reads
`self.past`) takes `&Acct` (or the `Past` value) as a parameter, and every
caller passes the accounts it read in the same call.

AC3. **Same behaviour.** Every existing test passes unchanged (the quota
tests in `quota.rs`, `s26.rs`, `regress_s25.rs`, `adv_s26.rs`, `regress_s26.rs`
and the S28-1 tests in `s28.rs`). One new test in `kernel/tests/it/s28.rs`
shows the flag is per call: owner `alice` past quota and owner `bob` not; a
call on alice's session (an item that would be dropped past quota, e.g. an
`Out` with a `message` entry) is followed by a call on bob's session that
writes an entry; bob's entry is stored, and alice's was not.

AC4. **Formatted.** `cargo fmt --check` in `kernel/` passes, with
`tests/it/adv_s26.rs` formatted (formatting only: `git diff -w` of that file
shows no change but line breaks and spacing).

AC5. **The spec says so.** In `design/TECHNICAL.md` 9.3 Quota, the "*Past.*"
bullet, after "Each is read before the call writes", add: "(as built (S28):
the flag lives only in the accounts the call read, never between calls)".
`factory/gate.sh` passes.

## Spec

Quoted rules this task follows:
- 9.3 Quota, *Past.*: "An owner is past its quota when its sessions are at
  the cap (for a new session) or its bytes are at or over its cap; the
  account is past when its bytes are at or over 224 MiB. Each is read before
  the call writes, so a call that starts below a cap may end over it by its
  own writes (at most one input and what it records); the next call finds it
  past."
- 9.3 Quota, "Any call when past (the owner or the account; a provider item,
  an owner's `answer`, `interrupt`, `cancel`, `unqueue`, the restart step, a
  timer, `attach`'s step)": the rules these functions implement stay as they
  are.
- Where the spec is unclear, stop and say so in your last message; do not
  pick a reading silently.
