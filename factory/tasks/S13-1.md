## Interface

Rules to write (fixed):
- R1 (9.4): "`attach` with an `after` that falls inside a group starts at the group's first
  part; `read` takes `after` as given." Reason, in one clause: a `read` that moved `after` back
  would return the same page again. A client that lost a group's start reads again with
  `after = i - n` (each part carries its `n`).
- R2 (2.3, 9.4): `read`'s `max` is 1 to 256. `max` 0 is `refused` with one refusal
  `{field: "max", reason}` (11's shape); a `max` over 256 reads as 256.
- R3 (7): "A call commits whole": the host-state writes of a call (host 7) commit together when
  its call chain commits, or not at all; a deferred or failed call leaves no write behind. So a
  failed `append` (9.4) leaves no chunk written and nothing charged to the owner (9.3, Quota).
- R4 (9.4): an `unreadable` entry keeps the index of its place: its chunk's first index (the
  record's `chunks`, 9.1) plus the line's position in the chunk; an `i` the stored line claims
  is ignored, so a corrupt line cannot take another entry's index.
- R5 (9.4): only the transcript store makes `part` entries, when it stores an entry over 256 KiB;
  `unreadable` is never stored. A session appends only the kinds of the table above other than
  `part`, made by the adapters (9.8) or the kernel itself, under a session id the kernel made;
  never a kind or id a caller names.
