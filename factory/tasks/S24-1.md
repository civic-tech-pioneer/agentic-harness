## Goal

`design/TECHNICAL.md` describes the state formats and rules that S21 built
(PR #25, "Decisions" and "For the PO") so that a kernel maker can rebuild them
from the spec alone. It also closes the RISK "`access/` covers `start` only":
it says how a child session's profile is allowed and what happens when a
client loses access to a profile while its session lives (fail closed). And
it says that R4's resume of an `idle` Claude session is owed to a later
slice that tracks provider streams. Documents only: `kernel/` and `console/`
are not touched. Code that differs from the new text goes to S20, listed in
9.4's "Code to change (S20)".

## Acceptance

Each item is one or more edits to `design/TECHNICAL.md`, in the section named.
Keep the spec's style: short sentences, section cross-references in
parentheses, no slice history except in a "Code to change" list.

AC1. 9.3 field list: the record gains `open` (the open asks and checks, each
`{id, kind, i, expires-at?}`: the ask id, `kind` `ask` or `check`, the index
`i` of its ask entry (9.4), and the ask entry's `expires-at` when it has one).
Say why: a decision entry can repeat its ask (9.4) after the adapter's memory
is gone (a restart), and `waiting.expires-at` (the earliest open ask's) is
recomputed without reading entries. An open ask leaves `open` when it is
decided or closed. The Sizes table gains an `open` row: one per open ask or
check, bounded as the asks are (the `deadlines` cap and `pending-answers`).

AC2. 9.1 `active/<n>`: the value is a JSON array of `[id, boot]` pairs (not
`{id, boot}` objects), with the reason: 256 entries with 64-byte ids then fit
the 24 KiB page. Every other place that writes "`{id, boot}`" for an
`active/` entry says the pair (search the file; `slots/wait/<n>` stays an
object).

AC3. 9.1 `access/<identity>`: the value is a JSON array of profile names. An
absent or unreadable value (not a JSON array of strings) allows none: fail
closed. `start` checks it before it reads `profile/<name>`, and refuses a
name not listed with the same refusal as a profile that does not exist
(`refused`, `{field: "profile"}`), so a client learns nothing about profiles
it may not use. The key is the caller's identity as `caller.identity()`
gives it (2.1).

AC4. 9.1 `key/<owner>/<key>` and `owner/<owner>/<n>`: `<owner>` is written
percent-encoded as one path segment (`%` to `%25`, then `/` to `%2F`),
because 2.1 identities contain `/` and the raw form is not one key per
(owner, key). A kept key's value is `{call, owner, session?, value}`
(`call`: `start`, `say` or `answer`; `session`: the session a `say` or
`answer` acted on; `value`: the result returned). The same key with another
call kind, owner or session is refused, one refusal `{field: "key"}`; a kept
result is never overwritten. Put the check in 9.3's bullet "`start` and `say`
and `answer` check `key/<owner>/<key>` first" or next to it.

AC5. 9.3 Sizes: the queue's 2 MiB counts stored bytes, each input as the
JSON string the queue stores (escapes included, without its quotes), so
`queue/<id>` and the `queue` push stay under the 4 MiB item. 9.1
`queue/<id>` names its value `{next, inputs: [{n, input}]}` (`input` the
input JSON as a string), and an emptied queue keeps `next`, so a number is
never used twice in one session (9.3 already says "numbered from 1 per
session"; make the two agree).

AC6. Owner pages: only `owner/<owner>/0` exists. A session past its 256
entries (a 257th live session of one owner) is refused `quota`. Say that more
pages come with the quota slice that raises the per-owner session cap past
256 (the default cap is 64, 9.3 Quota, so the page is not reached by
default). In 9.1's row and where 9.3 Quota names the session cap.

AC7. 9.2 compilation: a profile without `model` is checked against the
refuse table (11) with the model `"default"` (the backend's default model).

AC8. `access/` beyond `start`, as rules (9.1 row and 9.7, and 9.3 where a
call is named):
  a. A child session (9.7) is allowed by the parent's `delegates` and the
     narrowing of 9.7; its profile needs no entry in `access/`, because the
     child cannot widen its parent. Claude subagents are launch fields of the
     profile (4.1), not profiles, and need none either.
  b. Revoking: `access/` is read again by each call that would give a
     session more work: `say` (whether it starts a turn or queues),
     `interrupt` with a replacement, R5 Continue, the owner's `answer` with
     `allow`, and an OpenAI `task` that starts a child (checked against the
     root session's profile and owner). When `access/<owner>` no longer names
     the session's profile (or is absent or unreadable), such a call is
     refused `refused`, `{field: "profile"}` (a `task` call gets that refusal
     as its output), and a queued input is not started when a turn ends: the
     turn ends as it would, the queue is kept for `unqueue` or `delete`. Calls
     that only read or take power away still work: `read`, `attach`, `list`,
     `queued`, `unqueue`, `rename`, `answer` with `deny`, `interrupt` without
     a replacement, `cancel`, `take-back`, `delete`.
  c. A turn already running is not stopped by the change itself: no call of
     2.3 writes `access/` today, so the kernel learns of it only when it reads
     the key. State it as a limit, and that the slice that adds the call
     writing `access/` ends the turns of the sessions whose profile it
     removes (as `cancel`). Add this limit to 14's "Not protected" paragraph.

AC9. R4: the `idle` row says that a Claude session's next `say` resumes with
`session {resume}` only once the kernel tracks provider streams across a
restart; until the slice that adds that tracking, the kernel sends a fresh
session (`resume: false`). Name that as an owed item in a "Code to change"
list (9.4's "Code to change (S20)" is for S20; put this one under a heading
that names no slice, or under 9.3 with "a later slice"), not as the rule.

AC10. The smaller S21 decisions, each one sentence where its rule lives:
  a. `say` on `paused` with no `until` resumes (starts the turn); on a timed
     pause it queues (9.3 bullet on `say`).
  b. R5: when the queue is full, the `say` input is still taken: the turn
     starts with the oldest queued input first, then the new one joins the end
     of the queue, so order is kept and Continue is never refused
     `queue-full` for a queue that had room after the oldest left.
  c. R2: a `restart` firing whose session step fails marks that page entry
     current and goes on; R6 does the session's step when a call next reads
     its record.

AC11. 9.4 "Code to change (S20)": add a bullet for each AC whose rule the
S21 code does not yet follow. Check the code (`kernel/src/`) for each of
AC1–AC10; the expected ones are AC8 b (revoking: `say`, `interrupt`, R5,
`answer`, the turn end do not reread `access/`) and AC8 a if a child path
exists. AC9 is listed in its own place. Do not add bullets for rules the
code already follows.

AC12. `.claude/factory/check-docs.sh` passes and `factory/gate.sh` passes
