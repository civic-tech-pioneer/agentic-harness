# Review of ARCHITECTURE-PROPOSAL.md (2026-11-20)

A record. Two independent reviewers (security; architecture) read the proposal
as revised after the first decisions, with the specs and the spike. The PO
merged their findings and checked them. **Checked** means seen in a source, a
spec or a live run; **text** means the gap is in the proposal's own wording;
**open** means nobody has run it yet.

## Critical: the envelope leaks

1. **stdin is a second settings channel.** With `--input-format stream-json`,
   a stdin `control_request` `apply_flag_settings` merges an open settings map
   into the `--settings` layer of the live session, and `--restricted` keeps
   that layer. Other requests on the same channel: `initialize` with hooks,
   `mcp_set_servers`, and `updatedPermissions` in a `control_response`.
   **Checked live (claude 2.1.326):** asks off, `Write` not allowed; one
   `apply_flag_settings {"permissions":{"allow":["Write"]}}` line → the file
   was written; without it, refused. Hooks, env and MCP over this channel:
   open. Any mod that can `send` (provider, kernel through the unchecked
   pass-through, a tool provider that learns a stream id: 10) has full control.
   *Fix:* the host owns the stdin protocol. It sends `initialize` itself and
   accepts from mods only `user-message`, `answer(pending request id, allow |
   deny, updated input)` and `interrupt`, with `updatedPermissions` stripped. The
   rule "H1a never parses a protocol" was wrong.
2. **`tools` brings Bash and WebFetch back.** `--restricted` drops them "unless
   --tools names them" (claude --help, checked). With Bash, a session can read
   the Claude login from the keychain, `<home>/app/accounts/openai.json`, other
   streams' MCP configs, and call watane's loopback endpoints. *Fix:* a host
   allowlist of built-in tools without Bash, PowerShell and WebFetch; Bash only
   under its own grant ("can run any program as you") with a required sandbox:
   network denied, loopback included, no escape keys. `bash-sandbox` becomes a
   typed record.
3. **Skills are configuration.** `skill.name` has no grammar (a name `..`
   reaches the plugin root, where `hooks/hooks.json` and `.mcp.json` are native
   programs). SKILL.md frontmatter can carry `allowed-tools`, hooks and `!cmd`
   pre-expansion. A contributor answers the collect anonymously (W34). A
   contributed profile can take a participant's profile name. *Fix:* the host
   writes only `skills/<[a-z0-9-]{1,64}>/…`, generates `plugin.json`, parses
   the frontmatter and keeps only `name` and `description`; contributions carry
   their source; contributed profiles never replace or parent the participant's.
   Text; which frontmatter keys load: open.
4. **The ChatGPT token follows a field, not a destination.** "The host adds
   `Authorization` … only to an HTTPS source with `account: "openai"`": a mod
   with `[http] evil.example` and account consent sends the token there. The
   spike checked the host; the proposal dropped it. *Fix:* an account is bound
   to `https://api.openai.com` and a path allowlist; no redirects. Text.
5. **Argv injection.** `--allowedTools`, `--tools`, `--add-dir` and
   `--mcp-config` take several values; a value starting with `-` becomes a
   flag, and spaces and commas split rules. *Fix:* every value as one
   `--flag=value` argument, a grammar per field. Commander behaviour: open.

## Critical: authority goes to the wrong principal

6. **Confused deputy.** The host asks "Let {mod} work in {folder}?" for the mod
   that imports the host interface: the provider. Every kernel and client
   behind it inherits each workspace and toolset given once. Any client can
   start the participant's strongest profile, and `profiles.put` has no caller
   rule. Only the provider's plan shows the Claude Code words. *Fix:* the host
   carries the originating client down the chain (from the transport) and keys
   consent to (client, folder) and (client, toolset); profile edits only from
   the participant (caller `page`); every plan whose calls reach
   `watane:host/claude-code` says so. Text.
7. **Stream operations have no owner check.** A tool provider sees the caller
   `agent:stream-<id>`, so it knows the stream id and can `send` to claude's
   stdin (with 1: anything). `open` during a collect or an event floods the
   kernel. `stream-sink` and `stream-source` exports are callable through
   `/call` and toolsets. The consumer is defined twice ("the caller of the call
   that opened it" vs "the mod that called `start`"). *Fix:* random ids that are
   never handles; producer-only `push`/`close`, consumer-only `send`/`cancel`;
   the exports host-only, like subscriptions. Text.
8. **Consent cannot wait inside a call, and host effects have no commit point.**
   Consent waits up to 600 s (W19); a call returns within 10 s (Q1). W35
   requests return at once and act only when the call succeeds; the proposal
   starts `claude` inside a nested call. A later failure orphans the process
   (for example, `open` refused for an agent caller after `start` succeeded).
   *Fix:* `start` returns an id at once; the effect applies when the whole
   chain commits; "consent pending", "denied" and "binary missing" arrive on
   the stream. Checked against host 6.6 and 6.10.
9. **Writes are deferred code.** Under `--restricted` only "a person or the
   configured permission handler" approves writes to settings, git and
   tool-configuration files; here the handler is the mod chain. Writes to
   `.git/hooks/`, `.claude/`, `CLAUDE.md`, `.envrc` or build scripts run code
   later, outside any session. *Fix:* host-level deny rules for those paths; any
   exception only through the app. What project files load under
   `--restricted`: open.
10. **Workspace paths are unconstrained.** `/`, `~`, the watane home and
    `<home>/streams` (which holds other streams' tokens and plugin folders, and
    needs no consent) are all acceptable. *Fix:* canonical paths, symlinks
    resolved; refuse the home, its ancestors, `~/.claude`, `~/.ssh`; scratch
    folders in their own tree with host-chosen names. Text.
11. **Previews grant "Claude Code (unchecked)" without a question.** W5 and W27
    would start `claude` with the maker's real login and files for any mod in a
    preview. *Fix:* refuse it in a preview, or use a fake binary. Checked
    against W5.

## Major: the mechanism does not fit watane yet

12. **`toolset.call` deadlocks and escapes the cycle check.** It runs inside
    the kernel's item call, which holds the kernel's call mutex; a toolset that
    holds `agent:sessions.*` (as section 13 suggests) re-enters the kernel. The
    acyclic-links guarantee (host 6.6) does not cover dynamic toolset edges. A
    turn's tool step shares one 10 s chain; tokens are revoked when the HTTPS
    stream ends, which is when the tools run; the caller changes every turn.
    *Fix:* tool calls become top-level jobs whose results arrive as items;
    toolsets and the agent handle belong to the session, not to a stream.
13. **pkg refuses the worlds.** pkg 4.5 refuses imports of other `watane:*`
    interfaces and exports outside `mods:` (checked). `use
    watane:host/claude-code.{launch}` in the provider's interface makes the
    kernel import it, and so hold the grant (pkg 4.4: "interfaces pulled in by
    `use` are imports too", checked). No `Grant` kind, release encoding or app
    words exist. "Covered by the [http] grant" contradicts Http grants coming
    from the `wasi:http` import. *Fix:* types in a grant-free interface; pkg rows
    for each new import and the two exports; a new grant kind appended to the
    encoding.
14. **Contributors cannot also be clients.** A collect subscriber cannot call
    its collector (W34, checked). A factory mod that ships skills and starts
    sessions is refused with `cycle`. *Fix:* `start` takes the client's own
    skills and profile overlay as arguments; the collect is for third parties.
15. **Streams are under-specified.**
    - **No wake-up after `full`.** A reactor cannot "slow down": no call wakes
      it when the stream drains. Long `attach` replays fail.
    - **Page delivery is lossy.** Page delivery rides the shared broadcast bus
      (capacity 1024; a lagging page gets `changed`, checked). So items are
      lost, one stream can flood other mods' pages, and a closed tab never ends
      its stream.
    - **Delivery is unspecified.** There is no per-consumer queue. A caller for
      item calls is not defined. There are no hops or delivery limits; events
      have both (hops 8, deliveries 256, checked).
    - **Per-item cost.** Every item may cost a redb commit at each of three
      layers.

    *Fix:*
    - a `ready` callback or pull delivery;
    - a lossless per-connection queue for pages, which ends when the
      connection closes;
    - a per-consumer FIFO;
    - item calls with a defined caller;
    - limits;
    - coalesced deltas.
16. **Restart and resume contradict the folders.**
    - **Scratch sessions cannot resume.** The scratch folder dies with the
      stream, so a scratch session's resume finds nothing.
    - **Ids go stale or get reused.** Stream ids are memory-only, so after a
      restart they are stale or reused. Owner strings like `mod:<local>` are
      reused after a reinstall.
    - **No crash cleanup.** Nothing cleans up after a crash, and there is no
      process-group kill.

    *Fix:*
    - run folders outside every workspace, and scratch folders per session;
    - ids with a boot epoch;
    - owners as stable identities;
    - clean `streams/` at open;
    - kill the process group;
    - pass `--session-id` from the kernel.
17. **The checked provider judges too little and sees too much.**
    - **Pre-allowed tools skip the judge.** Tools pre-allowed by `allow` or the
      mode never produce an ask, so the judge never sees them.
    - **It is a full man in the middle.** It has network access to a host of
      its own choosing.
    - **"Checked" is only a claim.** Any mod with the same slug fits.
    - **Two contradictions.** Thresholds have no owner, and "cancels if the
      profile says so" has no field to read.
    - **SDK hook callbacks.** `PreToolUse` hook callbacks travel over stdio,
      not as native programs, and would show every tool call before it runs.
      They exist in the crate (checked); they work: open.

    *Fix:*
    - in checked mode, force every tool use through an ask, or use hook
      callbacks;
    - give the judge minimal excerpts;
    - show the judge host in the plan;
    - accept settings only from the participant.
18. **The envelope cannot evolve and has one wrong value.**
    - **Wrong value.** The CLI's modes are `manual`, `acceptEdits`, `auto`,
      `dontAsk`, `plan`, `bypassPermissions`: no `default` (checked).
    - **A hidden flag.** `--permission-prompt-tool` is not in `--help`.
    - **Resume can drop a field.** `--system-prompt-snapshot` is on by
      default, so a resume can drop a changed system prompt: the quiet drop that
      G4 forbids (checked).
    - **The record cannot grow.** A WIT record cannot gain a field inside a
      frozen `watane:host@0.1.0`.

    *Fix:*
    - correct the enum and decide on `auto`;
    - pass `--system-prompt-snapshot off`, or refuse a prompt change on resume;
    - make `launch` a versioned document that the host validates, with a
      minimum CLI version;
    - after `system/init`, compare tools, mode, MCP servers and plugins with
      the launch, and kill the process on a mismatch.
19. **The OpenAI subset quietly degrades.**
    - **Fields with no meaning.** `plan` and `accept-edits` have none without
      built-in tools.
    - **Claude rule syntax needs a reimplementation.** It needs a matcher of
      its own in the kernel.
    - **Skills lose their resources.**
    - **Effort levels.** `xhigh` and `max` have no OpenAI value.
    - **`persist: false`.** The kernel's own transcript defeats it.

    *Fix:* a refuse condition per field and backend, checked by the compiler.

## Minor and simplifications

- **Drop `stream-source`.** Input to a mod producer can go through the
  producer's own interface. Only host sources need `streams.send`.
- **The unchecked provider is a pure forwarder.** A host `hand-off` that
  re-targets a stream would keep the visible grant without the hop.
- **Two variants need two publishers.** A home holds one mod per publisher and
  slug, and a checked mod cannot import its own slug as a call. So the checked
  mod holds the host grant itself, and its plan must say so.
- **Contradiction on credentials.** The M1 row says "never holds a credential",
  but the judge's key lives in the provider's state.
- **SSE lines vs events.** An SSE event spans several lines; split HTTPS
  streams by event, not by line. Lines over 4 MiB need a rule.
- **Who owns the token file.** `app/` belongs to the app, but the host injects
  tokens and also runs without an app. The host needs an in-process token
  source.
- **F-AGENT-2 and W6.** They say only the app issues tokens, on the
  participant's request, and host 10.2 says tokens are never written to disk.
  The proposal mints tokens per stream and writes them to a file: amend the
  contracts, or pass the config through a pipe.
- **Environment pass-through.** Use an allowlisted environment. A GUI-launched
  app lacks the shell's PATH and `CLAUDE_CODE_OAUTH_TOKEN`.
- **Consent views must name the originating client and profile**, against
  consent phishing.
- **Missing limits.** Processes and streams per mod and in total; an
  idle/ask timeout; a size cap for `launch`.
- **Undefined types.** `stream-error`, `outcome`, `effort` and others.
- **Mod updates mid-session.** Not covered.

## What this changes in the design

1. **The host owns Claude's stdio protocol.** That covers the launch
   validation, the stdin filter, `initialize` and the check after `init`. Most
   Claude-specific security lives there; it is small, but it is protocol
   parsing in the trusted core.
2. **Host effects are requests.** They return at once, apply on commit and
   report on the stream (the W35 pattern).
3. **Authority follows the originating client.** Intermediaries do not take it.
4. **Tool calls are top-level jobs.** They are not nested calls.
5. **Streams need their own section in host.** Ownership, delivery queue,
   backpressure, page connections, limits.
6. **"Claude Code (unchecked)" means file tools in a confined folder.** Bash is
   a second, stronger grant with a required sandbox.
